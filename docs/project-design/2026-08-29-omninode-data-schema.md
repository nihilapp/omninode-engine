# 옴니노드 데이터 스키마

> 분류: 프로젝트 설계
>
> 근거: `2026-08-29-omninode-user-story-data-flow.md`, `2026-08-29-omninode-requirements-decisions.md`, 공통표준용어 커스텀 2025.11
>
> 범위: 데이터베이스의 테이블·컬럼·키·제약을 설계한다. ORM 코드, DDL, 마이그레이션, 데이터베이스 변경은 포함하지 않는다.

## 공통 명명 규칙

1. 모든 물리 테이블명과 컬럼명은 `snake_case`로 작성한다.
2. 물리 테이블명은 복수형으로 통일한다.
3. 모든 테이블의 기본 키는 `id` 컬럼이며 UUID v7을 사용한다.
4. 다른 테이블의 참조 컬럼은 대상 테이블 이름을 따른 `*_id` 형식이며 UUID v7을 사용한다.
5. 물리 식별자는 `G:\내 드라이브\공통표준용어`의 `공통표준용어 운영 지침.md`와 `공통표준용어 커스텀: 2025.11` 시트의 `DB 이름 짓기` 기준을 적용한다.
6. 새 식별자는 공통표준단어, 커스텀단어, 단어별칭을 함께 대조하고 `DB 이름 짓기`의 조합 결과를 적용한다. 직접 일치와 별칭의 우선순위는 공통표준용어 운영 지침을 따른다.
7. 이 문서에서 확인한 핵심 표준어는 어드민 `ADMIN`, 허가 `PRMSN`, 규칙 `RUL`, 월드 `WORLD`, 프로젝트 `PRJ`, 카테고리(범주) `CTGRY`, 템플릿(서식) `TMPLT`, 문서 `DOC`, 리비전 `RVS`, 섹션 `SECT`, 태그 `TAG`, 관계 `REL`이다.

## 모든 테이블의 공통 컬럼

모든 테이블에는 아래 여덟 컬럼을 공통으로 둔다.

| 의미 | 컬럼명 | 규칙 |
| --- | --- | --- |
| 사용 여부 | `use_yn` | 길이 1의 문자열이며 `Y` 또는 `N`만 허용한다. |
| 삭제 여부 | `del_yn` | 길이 1의 문자열이며 `Y` 또는 `N`만 허용한다. |
| 생성자 | `creatr_id` | 생성한 계정의 내부 ID를 기록한다. |
| 생성 날짜·시간 | `crt_dt` | `yyyy-MM-dd HH:mm:ss.sss` 정밀도로 생성 날짜·시간을 기록한다. |
| 수정자 | `mdfr_id` | 마지막으로 수정한 계정의 내부 ID를 기록한다. |
| 수정 날짜·시간 | `mdfcn_dt` | `yyyy-MM-dd HH:mm:ss.sss` 정밀도로 마지막 수정 날짜·시간을 기록한다. |
| 삭제자 | `dltr_id` | 삭제 처리한 계정의 내부 ID를 기록한다. |
| 삭제 날짜·시간 | `del_dt` | `yyyy-MM-dd HH:mm:ss.sss` 정밀도로 삭제 처리 날짜·시간을 기록한다. |

`creatr_id`, `mdfr_id`, `dltr_id`는 모두 `admins.id`를 참조한다. 서비스 최초 설치 때 직접 생성하는 최초 운영자 계정 한 건만 `creatr_id`를 비워 둘 수 있다. 시스템용 가상 계정은 만들지 않으며, 그 이후 생성되는 모든 데이터의 생성자·수정자·삭제자는 실제 로그인 관리자 계정으로 기록한다. 탈퇴 계정이 다른 관리자의 월드에 남긴 데이터는 유지하므로, 계정 완전 삭제 시 그 계정을 가리키는 남은 데이터의 이 세 참조는 비운다. 작성자 표시가 필요하면 비어 있는 탈퇴 계정 참조를 `탈퇴한 관리자`로 표시한다.

생성 직후처럼 수정 또는 삭제 작업이 아직 발생하지 않은 경우에는 `mdfr_id`, `mdfcn_dt`, `dltr_id`, `del_dt`를 비워 둔다. 해당 작업이 실제로 발생할 때만 값을 채운다.

새 행은 `use_yn`을 `Y`, `del_yn`을 `N`으로 시작한다. 사용 중지와 소프트 딜리트는 별개 상태이므로 삭제 처리와 복구는 `use_yn`을 바꾸지 않는다.

## 관리자 로그인 정보

- 운영자·관리자·부관리자를 관리하는 물리 테이블은 `admins`로 둔다.
- `admins`에는 로그인에 필요한 계정 정보와 인증 정보를 함께 저장한다. 별도의 `accounts` 테이블은 만들지 않는다.
- `admins`는 공통표준용어 커스텀단어의 어드민 `ADMIN`을 적용한 이름이다.
- 역할 배정은 `admin_roles`에서 관리한다. 이 테이블은 운영자·관리자·부관리자 역할을 모두 관리하며, 운영자 역할은 월드 없이, 관리자·부관리자 역할은 대상 월드와 함께 기록한다.
- 관리자 세부 허가는 역할 배정과 분리한 `admin_prmsn_ruls` 테이블에서 관리한다. 이 이름은 커스텀단어의 어드민 `ADMIN`과 표준어 허가 `PRMSN`, 규칙 `RUL`을 조합한 것이다.
- 각 행은 `id`, `admin_id`, `world_id`, `prj_id`와 24개 허가 컬럼을 가진다.
- 24개 허가 컬럼은 월드 관리, 프로젝트 관리, 부관리자 초대, 카테고리 관리, 템플릿 관리, 문서 관리, 태그 관리, 관계 관리의 생성·수정·삭제 허가로 구성한다. 관계 관리는 기본 관계 유형의 월드별 활성화·비활성화, 사용자 정의 관계 유형·역할·허용 카테고리, 실제 관계 인스턴스를 함께 관리하는 대상이다.
- 운영자·관리자·부관리자 모두 `admin_prmsn_ruls` 레코드를 가진다. 실제 작업 가능 여부는 역할명만으로 우회하지 않고 이 테이블의 24개 허가 컬럼으로 판단한다.
- 운영자는 전역 범위에서 24개 허가를 모두 `Y`로 시작한다. 관리자와 부관리자는 자신에게 적용되는 월드 또는 프로젝트 범위에서 허가를 가진다. 부관리자의 각 허가값은 관리자 설정에 따라 `Y` 또는 `N`으로 저장한다.
- `world_id`가 비어 있으면 전역 범위의 허가이며, 이때 `prj_id`도 비워 둔다. 월드 생성 허가를 받은 어드민은 전역 범위 행에서 `world_crt_yn`만 `Y`로 가진다. `world_id`가 있으면 해당 월드 범위의 허가이고, `prj_id`가 비어 있으면 월드 전체 범위이며 값이 있으면 해당 프로젝트 범위다.
- 탈퇴 계정이 완전 삭제되면 `admin_roles`, `admin_prmsn_ruls`, 미완료 비밀번호 재설정 요청은 함께 제거한다. 과거 초대·감사 이력의 대상 계정 참조와 다른 월드에 남은 데이터의 공통 작성자·수정자·삭제자 참조는 비워 기록을 유지한다.

### `admins`

`admins`는 한 로그인 주체당 한 행을 가진다. 모든 테이블의 생성자·수정자·삭제자 참조 대상이다. 아래 표의 공통 컬럼 여덟 개도 함께 가진다.

| 컬럼 | 형식 | 필수 | 제약·설명 |
| --- | --- | --- | --- |
| `id` | UUID v7 | 예 | 기본 키 |
| `eml` | 문자열 | 예 | 로그인 이메일. 활성·미삭제 행에서는 중복될 수 없다. |
| `indct_nm` | 문자열 | 예 | 실명이 아닌 표시 이름 |
| `pswd_hash` | 문자열 | 예 | 비밀번호 원문 대신 해시값을 저장한다. |
| `tmpr_pswd_yn` | 문자열(1) | 예 | 임시 비밀번호 상태 여부. `Y` 또는 `N`만 허용한다. 새 관리자 또는 새 부관리자는 `Y`, 최초 비밀번호 변경 뒤 `N`이다. |

### `admin_roles`

`admin_roles`는 한 어드민의 전역 또는 월드별 역할을 기록한다. 아래 표의 공통 컬럼 여덟 개도 함께 가진다.

| 컬럼 | 형식 | 필수 | 제약·설명 |
| --- | --- | --- | --- |
| `id` | UUID v7 | 예 | 기본 키 |
| `admin_id` | UUID v7 | 예 | `admins.id` 참조 |
| `world_id` | UUID v7 | 아니오 | `worlds.id` 참조. 운영자 역할일 때만 비워 둔다. |
| `role_type_cd` | 문자열 | 예 | 운영자, 관리자, 부관리자 중 하나를 기록한다. |

`world_id`가 비어 있는 행은 `role_type_cd`가 운영자일 때만 허용하며, 운영자 역할은 한 계정에 활성·미삭제 행 하나만 둔다. `world_id`가 있는 행은 관리자 또는 부관리자 역할만 허용하며, 같은 계정과 월드 조합에는 활성·미삭제 역할 행 하나만 둔다. 따라서 한 사람이 같은 월드에서 관리자와 부관리자 역할을 함께 가지지 않는다.

### `admin_prmsn_ruls`

`admin_prmsn_ruls`는 역할과 무관하게 실제 작업 허가를 판단하는 테이블이다. 아래 표의 공통 컬럼 여덟 개도 함께 가진다. 허가 컬럼은 모두 문자열(1)이며 `Y` 또는 `N`만 허용하고, 기본값은 `N`이다.

| 컬럼 | 형식 | 필수 | 제약·설명 |
| --- | --- | --- | --- |
| `id` | UUID v7 | 예 | 기본 키 |
| `admin_id` | UUID v7 | 예 | `admins.id` 참조 |
| `world_id` | UUID v7 | 아니오 | `worlds.id` 참조. 비어 있으면 전역 범위이며 이때 `prj_id`도 비워 둔다. |
| `prj_id` | UUID v7 | 아니오 | `prjs.id` 참조. `world_id`가 있을 때만 입력할 수 있다. 비어 있으면 월드 전체 범위다. |
| `world_crt_yn`, `world_mdfcn_yn`, `world_del_yn` | 문자열(1) | 예 | 월드 생성·수정·삭제 허가 |
| `prj_crt_yn`, `prj_mdfcn_yn`, `prj_del_yn` | 문자열(1) | 예 | 프로젝트 생성·수정·삭제 허가 |
| `admin_invit_crt_yn`, `admin_invit_mdfcn_yn`, `admin_invit_del_yn` | 문자열(1) | 예 | 부관리자 초대 생성·수정·삭제 허가 |
| `ctgry_crt_yn`, `ctgry_mdfcn_yn`, `ctgry_del_yn` | 문자열(1) | 예 | 카테고리 생성·수정·삭제 허가 |
| `tmplt_crt_yn`, `tmplt_mdfcn_yn`, `tmplt_del_yn` | 문자열(1) | 예 | 템플릿 생성·수정·삭제 허가 |
| `doc_crt_yn`, `doc_mdfcn_yn`, `doc_del_yn` | 문자열(1) | 예 | 문서 생성·수정·삭제 허가 |
| `tag_crt_yn`, `tag_mdfcn_yn`, `tag_del_yn` | 문자열(1) | 예 | 태그 생성·수정·삭제 허가 |
| `rel_crt_yn`, `rel_mdfcn_yn`, `rel_del_yn` | 문자열(1) | 예 | 관계 유형·역할·허용 카테고리와 실제 관계 인스턴스의 생성·수정·삭제 허가 |

활성·미삭제 허가 규칙은 같은 `admin_id`, `world_id`, `prj_id` 범위 조합에 하나만 둔다. 실제 허가는 가장 좁은 범위의 행을 우선 적용하고, 그 범위에 행이 없을 때만 상위 월드 범위 또는 전역 범위를 적용한다. 월드·프로젝트 범위와 무관한 운영자 전역 행은 24개 허가를 모두 `Y`로 유지한다. 부관리자 역할의 허가 행에서는 월드 관리, 부관리자 초대, 관계 관리, 태그 목록 관리의 각 생성·수정·삭제 허가를 모두 `N`으로 고정한다. 문서 작성·수정 허가에 포함되는 태그 연결·해제와 새 태그 자동 추가는 `tag_*_yn`이 아니라 `doc_*_yn`으로 판단한다.

## 월드

### `worlds`

`worlds`는 한 창작 세계관의 최상위 범위를 기록한다. 아래 표의 공통 컬럼 여덟 개도 함께 가진다. 월드 공개 상태는 별도로 저장하지 않는다. 현재 기획에서 뷰어 노출의 기준은 월드가 아니라 관리자가 공개 반영한 문서이기 때문이다.

| 컬럼 | 형식 | 필수 | 제약·설명 |
| --- | --- | --- | --- |
| `id` | UUID v7 | 예 | 기본 키 |
| `admin_id` | UUID v7 | 예 | 현재 월드 소유자. `admins.id`를 참조한다. 탈퇴에 따른 소유권 승계 시 변경할 수 있다. |
| `world_cd` | 문자열 | 예 | 월드 생성자가 직접 입력하는, UUID와 별도로 공개 주소에서 월드를 식별하는 변경 불가 슬러그. 한글, 영문 대소문자, 숫자, 하이픈만 허용하며 영문 대소문자를 구분하지 않는다. |
| `world_nm` | 문자열 | 예 | 월드 이름 |

`del_yn`이 `N`인 행만을 대상으로 같은 `creatr_id` 안에서 `world_nm`이 중복될 수 없다. 이는 같은 관리자가 새로 만든 월드끼리만 이름 중복을 막는 규칙이며, 소유권 이전 뒤의 현재 소유자는 이 검사 기준이 아니다. 삭제된 같은 이름의 월드는 복구 또는 별도 새 생성을 선택할 수 있으므로, 삭제된 행은 이 중복 제약의 대상에 포함하지 않는다. `world_cd`는 영문 대소문자를 구분하지 않고 서비스 전체에서 중복될 수 없으며 생성 뒤 바꿀 수 없다. 공개 주소의 `world_cd` 해석도 영문 대소문자를 구분하지 않는다. 월드 소유자 탈퇴를 확정할 때 부관리자가 있으면, 탈퇴자가 지정한 부관리자의 `admin_id`로 이 값을 즉시 바꾸고 해당 역할을 관리자로 승격한다. 부관리자가 없을 때만 월드와 하위 데이터를 완전 삭제한다.

새 월드를 만들면 `worlds.admin_id`의 계정에 해당 월드의 관리자 `admin_roles` 행과, 24개 허가가 모두 `Y`인 월드 범위 `admin_prmsn_ruls` 행을 함께 만든다. 이후 탈퇴에 따른 소유권 승계가 발생하면 같은 방식으로 지정 부관리자를 현재 월드 소유자·관리자로 바꾼다.

## 프로젝트

### `prjs`

`prjs`는 월드 안에서 작품 단위를 기록한다. 아래 표의 공통 컬럼 여덟 개도 함께 가진다. 프로젝트 공개 상태도 별도로 저장하지 않으며, 공개 여부는 문서의 공개 반영 상태로 판단한다.

| 컬럼 | 형식 | 필수 | 제약·설명 |
| --- | --- | --- | --- |
| `id` | UUID v7 | 예 | 기본 키 |
| `world_id` | UUID v7 | 예 | 소속 월드. `worlds.id`를 참조한다. |
| `prj_cd` | 문자열 | 예 | 프로젝트 생성자가 직접 입력하는, UUID와 별도로 공개 주소에서 프로젝트를 식별하는 변경 불가 슬러그. 한글, 영문 대소문자, 숫자, 하이픈만 허용하며 영문 대소문자를 구분하지 않는다. |
| `prj_nm` | 문자열 | 예 | 프로젝트 이름 |

`del_yn`이 `N`인 행만을 대상으로 같은 `world_id` 안에서 `prj_nm`이 중복될 수 없다. 삭제된 같은 이름의 프로젝트는 복구 또는 별도 새 생성을 선택할 수 있으므로, 삭제된 행은 이 중복 제약의 대상에 포함하지 않는다. `prj_cd`는 영문 대소문자를 구분하지 않고 같은 `world_id` 안에서 중복될 수 없으며 생성 뒤 바꿀 수 없다. 공개 주소의 `prj_cd` 해석도 영문 대소문자를 구분하지 않는다.

## 카테고리와 템플릿 연결

### `ctgrys`

`ctgrys`는 시스템 기본 카테고리와 프로젝트 사용자 정의 카테고리의 정의를 함께 기록한다. 기본 카테고리는 프로젝트가 생성할 때 복제하지 않고 이 테이블의 정의를 그대로 참조한다. 부모 카테고리를 가리키는 방식으로 깊이를 계산하므로, 별도의 단계 컬럼은 두지 않는다. 아래 표의 공통 컬럼 여덟 개도 함께 가진다.

| 컬럼 | 형식 | 필수 | 제약·설명 |
| --- | --- | --- | --- |
| `id` | UUID v7 | 예 | 기본 키 |
| `prj_id` | UUID v7 | 아니오 | 사용자 정의 카테고리의 소속 프로젝트. `prjs.id`를 참조한다. 비어 있으면 시스템 기본 카테고리다. |
| `prnt_ctgry_id` | UUID v7 | 아니오 | 상위 카테고리. `ctgrys.id`를 참조한다. 비어 있으면 대분류다. |
| `ctgry_cd` | 문자열 | 예 | 변경할 수 없는 카테고리 코드 |
| `ctgry_nm` | 문자열 | 예 | 카테고리 이름 |

카테고리 깊이는 대분류부터 최대 3단계로 제한한다. `prj_id`가 비어 있으면 시스템 기본 카테고리이고, 값이 있으면 해당 프로젝트에서만 사용할 수 있는 사용자 정의 카테고리다. 사용자 정의 카테고리는 `prnt_ctgry_id`를 비워 대분류로 만들 수 있고, 같은 프로젝트의 사용자 정의 카테고리 또는 시스템 기본 카테고리를 상위 카테고리로 가리킬 수도 있다. 시스템 기본 카테고리는 수정·삭제할 수 없고, 코드도 변경할 수 없다.

시스템 기본 카테고리의 `ctgry_cd`는 서비스 전체에서 중복될 수 없고, 사용자 정의 카테고리의 `ctgry_cd`는 같은 `prj_id` 안에서 중복될 수 없다. `del_yn`이 `N`인 행만을 대상으로 같은 `prj_id`와 같은 `prnt_ctgry_id` 안에서 `ctgry_nm`이 중복될 수 없다.

### `prj_ctgrys`

`prj_ctgrys`는 프로젝트가 참조하는 카테고리와 프로젝트별 설정을 기록한다. 시스템 기본 카테고리의 사용 여부, 프로젝트 안의 표시 순서, 대분류와 템플릿의 연결은 이 테이블에서 관리한다. 사용자 정의 카테고리도 같은 구조로 참조해 프로젝트별 카테고리 구성을 일관되게 관리한다. 아래 표의 공통 컬럼 여덟 개도 함께 가진다.

| 컬럼 | 형식 | 필수 | 제약·설명 |
| --- | --- | --- | --- |
| `id` | UUID v7 | 예 | 기본 키 |
| `prj_id` | UUID v7 | 예 | 대상 프로젝트. `prjs.id`를 참조한다. |
| `ctgry_id` | UUID v7 | 예 | 참조할 카테고리 정의. `ctgrys.id`를 참조한다. |
| `ctgry_seq` | 정수 | 예 | 같은 상위 카테고리 안에서의 프로젝트별 표시 순서 |
| `prj_tmplt_id` | UUID v7 | 아니오 | 대분류에 연결한 프로젝트 템플릿 참조. `prj_tmplts.id`를 참조한다. 템플릿이 없는 대분류는 문서를 작성할 수 없다. |
| `ctgry_mvmn_chck_yn` | 문자열(1) | 예 | 카테고리 이동 뒤 이 카테고리의 템플릿 연결을 점검해야 하는지 여부. `Y` 또는 `N`만 허용한다. |

같은 `prj_id` 안에서 `ctgry_id`는 중복될 수 없다. `ctgry_id`가 사용자 정의 카테고리이면 그 카테고리의 `ctgrys.prj_id`는 이 행의 `prj_id`와 같아야 한다. `prj_tmplt_id`는 대분류에만 입력할 수 있으며, 같은 `prj_id`의 프로젝트 템플릿 참조만 연결할 수 있다. 하나의 프로젝트 템플릿은 여러 대분류 카테고리에서 함께 참조할 수 있다. `use_yn`은 해당 프로젝트에서 카테고리를 선택할 수 있는지를 뜻하며, 시스템 기본 카테고리의 활성화·비활성화도 이 값으로 관리한다.

새 프로젝트를 만들면 모든 시스템 기본 카테고리를 참조하는 `prj_ctgrys` 행을 `use_yn='Y'`, `ctgry_mvmn_chck_yn='N'`으로 함께 만든다. 카테고리를 다른 상위 카테고리 아래로 이동하면 영향받는 카테고리 연결은 `ctgry_mvmn_chck_yn='Y'`로 바꾸며, 관리자가 직접 구조 점검을 끝낸 경우에만 다시 `N`으로 바꾼다.

## 템플릿과 템플릿 리비전

### `tmplt_sects`

`tmplt_sects`는 템플릿 안에서 한 번 만들어진 섹션 코드의 영속 식별자를 기록한다. 리비전별 라벨·순서·레벨은 이 테이블이 아니라 `tmplt_rvs_sects`에서 보존한다. 아래 표의 공통 컬럼 여덟 개도 함께 가진다.

| 컬럼 | 형식 | 필수 | 제약·설명 |
| --- | --- | --- | --- |
| `id` | UUID v7 | 예 | 기본 키 |
| `tmplt_id` | UUID v7 | 예 | 대상 템플릿. `tmplts.id`를 참조한다. |
| `sect_cd` | 문자열 | 예 | 템플릿 안에서 자동 생성하는 변경 불가 섹션 코드 |

같은 `tmplt_id` 안에서 `sect_cd`는 중복될 수 없다. 한 번 생성한 행의 코드와 소속 템플릿은 바꾸거나 삭제하지 않는다. 템플릿 섹션 제거가 필요한 경우에는 이 행을 삭제하지 않고 다른 템플릿을 새로 만든다.

### `tmplts`

`tmplts`는 시스템 기본 템플릿과 프로젝트 사용자 정의 템플릿의 정의·현재 적용 리비전을 기록한다. 기본 템플릿은 프로젝트를 만들 때 복제하지 않고 이 테이블의 정의를 그대로 참조한다. 아래 표의 공통 컬럼 여덟 개도 함께 가진다.

| 컬럼 | 형식 | 필수 | 제약·설명 |
| --- | --- | --- | --- |
| `id` | UUID v7 | 예 | 기본 키 |
| `prj_id` | UUID v7 | 아니오 | 사용자 정의 템플릿의 소속 프로젝트. `prjs.id`를 참조한다. 비어 있으면 시스템 기본 템플릿이다. |
| `tmplt_cd` | 문자열 | 예 | 변경할 수 없는 템플릿 코드 |
| `tmplt_nm` | 문자열 | 예 | 템플릿 이름 |
| `now_tmplt_rvs_id` | UUID v7 | 예 | 현재 적용 중인 템플릿 리비전. `tmplt_rvss.id`를 참조한다. |

`prj_id`가 비어 있으면 시스템 기본 템플릿이고, 값이 있으면 해당 프로젝트에서만 사용할 수 있는 사용자 정의 템플릿이다. 시스템 기본 템플릿은 수정·삭제할 수 없고, 코드도 변경할 수 없다. 시스템 기본 템플릿의 `tmplt_cd`는 서비스 전체에서 중복될 수 없고, 사용자 정의 템플릿의 `tmplt_cd`는 같은 `prj_id` 안에서 중복될 수 없다. `del_yn`이 `N`인 행만을 대상으로 같은 `prj_id` 안에서 `tmplt_nm`이 중복될 수 없다. 사용 중인 사용자 정의 템플릿은 삭제하지 않고 비활성화만 할 수 있으며, 참조가 없어진 경우에만 삭제할 수 있다. `tmplts`와 최초 `tmplt_rvss`는 하나의 트랜잭션에서 만들며, 행 생성 중에만 `now_tmplt_rvs_id`를 비워 둘 수 있고 완료 시에는 반드시 최초 리비전을 가리킨다.

### `prj_tmplts`

`prj_tmplts`는 프로젝트가 참조하는 템플릿과 프로젝트별 사용 설정을 기록한다. 시스템 기본 템플릿의 활성화·비활성화와 사용자 정의 템플릿의 사용 상태를 이 테이블에서 관리한다. 아래 표의 공통 컬럼 여덟 개도 함께 가진다.

| 컬럼 | 형식 | 필수 | 제약·설명 |
| --- | --- | --- | --- |
| `id` | UUID v7 | 예 | 기본 키 |
| `prj_id` | UUID v7 | 예 | 대상 프로젝트. `prjs.id`를 참조한다. |
| `tmplt_id` | UUID v7 | 예 | 참조할 템플릿 정의. `tmplts.id`를 참조한다. |

같은 `prj_id` 안에서 `tmplt_id`는 중복될 수 없다. `tmplt_id`가 사용자 정의 템플릿이면 그 템플릿의 `tmplts.prj_id`는 이 행의 `prj_id`와 같아야 한다. `use_yn`은 해당 프로젝트에서 템플릿을 새 카테고리에 연결하거나 새 문서를 작성할 때 사용할 수 있는지를 뜻한다.

새 프로젝트를 만들면 모든 시스템 기본 템플릿을 참조하는 `prj_tmplts` 행을 `use_yn='Y'`로 함께 만든다.

### `tmplt_rvss`

`tmplt_rvss`는 템플릿을 생성하거나 수정할 때마다 만드는 템플릿 상태의 리비전이다. 과거 리비전을 현재 적용 리비전으로 되돌릴 때에는 새 행을 만들지 않고 `tmplts.now_tmplt_rvs_id`만 바꾼다. 아래 표의 공통 컬럼 여덟 개도 함께 가진다.

| 컬럼 | 형식 | 필수 | 제약·설명 |
| --- | --- | --- | --- |
| `id` | UUID v7 | 예 | 기본 키 |
| `tmplt_id` | UUID v7 | 예 | 대상 템플릿. `tmplts.id`를 참조한다. |
| `bfr_tmplt_rvs_id` | UUID v7 | 아니오 | 이 리비전이 기반으로 삼은 이전 템플릿 리비전. `tmplt_rvss.id`를 참조한다. 최초 리비전은 비워 둔다. |
| `rvs_seq` | 정수 | 예 | 사람이 확인하는 템플릿 리비전 표시 순번 |

같은 `tmplt_id` 안에서 `rvs_seq`는 중복될 수 없다. 리비전 계보 판단은 `rvs_seq`가 아니라 `bfr_tmplt_rvs_id`를 사용한다.

### `tmplt_rvs_sects`

`tmplt_rvs_sects`는 하나의 템플릿 리비전에 속한 섹션 구조의 스냅샷이다. 문서 리비전은 이 구조의 변경 불가 섹션 코드를 참조한다. 아래 표의 공통 컬럼 여덟 개도 함께 가진다.

| 컬럼 | 형식 | 필수 | 제약·설명 |
| --- | --- | --- | --- |
| `id` | UUID v7 | 예 | 기본 키 |
| `tmplt_rvs_id` | UUID v7 | 예 | 소속 템플릿 리비전. `tmplt_rvss.id`를 참조한다. |
| `tmplt_sect_id` | UUID v7 | 예 | 영속 템플릿 섹션. `tmplt_sects.id`를 참조한다. |
| `sect_cd` | 문자열 | 예 | `tmplt_sect_id`가 가리키는 변경 불가 섹션 코드를 리비전 식별에 함께 기록한다. |
| `sect_lbl` | 문자열 | 예 | 섹션 헤딩으로 표시할 라벨 |
| `sect_seq` | 정수 | 예 | 템플릿 안에서의 섹션 표시 순서 |
| `sect_level` | 정수 | 예 | 헤딩 레벨 |
| `esntl_yn` | 문자열(1) | 예 | 필수 섹션 여부. `Y` 또는 `N`만 허용한다. |

같은 `tmplt_rvs_id` 안에서 `tmplt_sect_id`, `sect_cd`, `sect_seq`는 각각 중복될 수 없다. `sect_cd`는 연결한 `tmplt_sects.sect_cd`와 같아야 한다. 최초 템플릿 리비전 뒤 새 리비전을 만들 때에는 기존 `tmplt_sects`의 섹션을 모두 포함해야 하며, 새 선택 섹션을 추가할 때에만 새 `tmplt_sects` 행을 함께 만든다. 첫 필수 섹션은 항상 `개요`이며, 그 위에 섹션을 추가할 수 없다. 선택 섹션은 필수 섹션 사이에 둘 수 있으나, 직전 구조가 허용하는 같은 레벨 또는 더 하위 레벨만 사용할 수 있다. 섹션 코드의 삭제·변경은 허용하지 않으며, 다른 구조가 필요하면 새 템플릿을 만든다.

## 문서와 문서 리비전

### `docs`

`docs`는 문서의 현재 식별·범위·공개 상태를 기록한다. 본문, 카테고리, 템플릿 리비전, 이름의 시점별 상태는 `doc_rvss`에서 보존한다. 아래 표의 공통 컬럼 여덟 개도 함께 가진다.

| 컬럼 | 형식 | 필수 | 제약·설명 |
| --- | --- | --- | --- |
| `id` | UUID v7 | 예 | 기본 키 |
| `world_id` | UUID v7 | 예 | 소속 월드. `worlds.id`를 참조한다. 같은 월드 안의 문서만 위키링크 대상으로 선택할 수 있다. |
| `prj_id` | UUID v7 | 예 | 소속 프로젝트. `prjs.id`를 참조한다. |
| `doc_nm` | 문자열 | 예 | 괄호 구분 표기까지 포함한 문서상 이름. 슬래시 구분은 최대 3개 구간까지 허용하며, 폴더 구조를 뜻하지 않는다. |
| `indct_nm` | 문자열 | 예 | 괄호 구분 표기를 제외한 표시 이름 |
| `now_doc_rvs_id` | UUID v7 | 예 | 현재 문서 리비전. `doc_rvss.id`를 참조한다. |
| `rls_yn` | 문자열(1) | 예 | 현재 공개 여부. `Y` 또는 `N`만 허용하며 새 문서는 `N`으로 시작한다. |
| `rls_doc_rvs_id` | UUID v7 | 아니오 | 현재 뷰어에게 공개할 문서 리비전. `doc_rvss.id`를 참조한다. 비공개 전환 뒤에도 이전 값을 보존한다. |
| `ctgry_mvmn_chck_yn` | 문자열(1) | 예 | 카테고리 이동 뒤 문서 구조를 점검해야 하는지 여부. `Y` 또는 `N`만 허용한다. |

`prj_id`는 `world_id`가 가리키는 월드에 속해야 하며, `rls_doc_rvs_id`는 같은 `doc_id`의 문서 리비전만 가리킬 수 있다. `del_yn`이 `N`인 행만을 대상으로 같은 `prj_id` 안에서 `doc_nm`이 중복될 수 없다. `doc_nm`의 슬래시는 최대 3개 경로 구간을 구분할 수 있으나, 별도 폴더 데이터·권한·카테고리 구조를 만들지 않는다. `indct_nm`은 같은 프로젝트 안에서도 중복될 수 있다. 문서상 이름과 표시 이름은 일반 문서 수정이 아닌 문서 관리 기능에서만 바꾸며, 이름 변경 결과는 새 문서 리비전에 함께 보존한다. `docs`와 최초 `doc_rvss`는 하나의 트랜잭션에서 만들며, 행 생성 중에만 `now_doc_rvs_id`를 비워 둘 수 있고 완료 시에는 반드시 최초 리비전을 가리킨다. `ctgry_mvmn_chck_yn='Y'`인 문서는 `rls_yn='Y'`로 공개할 수 없다. 카테고리 이동으로 영향을 받으면 즉시 `rls_yn`을 `N`으로 바꾸고, 관리자가 직접 구조 점검을 완료한 경우에만 `ctgry_mvmn_chck_yn`을 `N`으로 바꿔 다시 공개할 수 있게 한다.

### `doc_rvss`

`doc_rvss`는 사용자가 `저장`할 때마다 만드는 문서의 시점별 상태다. 문서 생성 시 빈 첫 리비전을 즉시 만들고, 과거 리비전을 현재 상태로 되돌릴 때에는 새 행을 만들지 않는다. 되돌린 상태를 수정해 저장하면, 그 되돌린 리비전을 이전 리비전으로 가리키는 새 행을 만든다. 첫 버전에는 자동 임시 초안 테이블을 두지 않는다. 세계관 안의 시작·종료 시점은 날짜·시간 형식으로 제한하지 않는 문자열로 보존한다. 아래 표의 공통 컬럼 여덟 개도 함께 가진다.

| 컬럼 | 형식 | 필수 | 제약·설명 |
| --- | --- | --- | --- |
| `id` | UUID v7 | 예 | 기본 키 |
| `doc_id` | UUID v7 | 예 | 대상 문서. `docs.id`를 참조한다. |
| `bfr_doc_rvs_id` | UUID v7 | 아니오 | 이 리비전이 기반으로 삼은 이전 문서 리비전. `doc_rvss.id`를 참조한다. 최초 리비전은 비워 둔다. |
| `rvs_seq` | 정수 | 예 | 사람이 확인하는 문서 리비전 표시 순번 |
| `ctgry_id` | UUID v7 | 예 | 이 리비전에서 적용한 카테고리. `ctgrys.id`를 참조한다. |
| `tmplt_rvs_id` | UUID v7 | 예 | 이 리비전에서 적용한 템플릿 리비전. `tmplt_rvss.id`를 참조한다. |
| `doc_nm` | 문자열 | 예 | 이 리비전 시점의 문서상 이름. 슬래시 구분은 최대 3개 구간까지 허용하며, 폴더 구조를 뜻하지 않는다. |
| `indct_nm` | 문자열 | 예 | 이 리비전 시점의 표시 이름 |
| `bgng_pstn` | 문자열 | 아니오 | 이 리비전 시점의 세계관 안 시작 시점. 날짜·시대·연표 등 다양한 표기를 그대로 기록한다. |
| `end_pstn` | 문자열 | 아니오 | 이 리비전 시점의 세계관 안 종료 시점. 날짜·시대·연표 등 다양한 표기를 그대로 기록한다. |

같은 `doc_id` 안에서 `rvs_seq`는 중복될 수 없다. `ctgry_id`는 문서의 `prj_id`가 참조하는 카테고리여야 하며, `tmplt_rvs_id`는 해당 카테고리의 대분류가 `prj_ctgrys.prj_tmplt_id`로 연결한 `prj_tmplts`의 템플릿 리비전이어야 한다. 리비전 계보 판단은 `rvs_seq`가 아니라 `bfr_doc_rvs_id`를 사용한다. 현재 공개 상태와 뷰어용 공개 리비전 선택은 `docs.rls_yn`, `docs.rls_doc_rvs_id`에서 관리하므로, 공개 반영 또는 비공개 전환만으로는 `doc_rvss`를 새로 만들지 않는다.

### `doc_rvs_sects`

`doc_rvs_sects`는 문서 리비전별 섹션 본문과 표시 구조의 스냅샷이다. 템플릿 섹션을 사용한 행은 당시의 템플릿 리비전 섹션을 함께 가리키고, 문서에 직접 추가한 섹션은 해당 참조 없이 독립된 섹션 코드로 기록한다. 아래 표의 공통 컬럼 여덟 개도 함께 가진다.

| 컬럼 | 형식 | 필수 | 제약·설명 |
| --- | --- | --- | --- |
| `id` | UUID v7 | 예 | 기본 키 |
| `doc_rvs_id` | UUID v7 | 예 | 소속 문서 리비전. `doc_rvss.id`를 참조한다. |
| `tmplt_rvs_sect_id` | UUID v7 | 아니오 | 연결된 템플릿 리비전 섹션. `tmplt_rvs_sects.id`를 참조한다. 문서 직접 추가 섹션은 비워 둔다. |
| `sect_cd` | 문자열 | 예 | 문서 리비전 안에서 변경하지 않는 섹션 코드 |
| `sect_lbl` | 문자열 | 예 | 이 리비전에서 표시할 섹션 라벨 |
| `sect_seq` | 정수 | 예 | 이 리비전에서의 섹션 표시 순서 |
| `sect_level` | 정수 | 예 | 이 리비전에서의 헤딩 레벨 |
| `esntl_yn` | 문자열(1) | 예 | 이 리비전에서의 필수 섹션 여부. `Y` 또는 `N`만 허용한다. |
| `sect_cn` | 문자열 | 예 | 섹션별 본문 내용 |

같은 `doc_rvs_id` 안에서 `sect_cd`와 `sect_seq`는 각각 중복될 수 없다. 템플릿 섹션을 쓰는 행의 `sect_cd`, `sect_lbl`, `sect_seq`, `sect_level`, `esntl_yn`은 연결한 `tmplt_rvs_sects`의 해당 시점 값을 저장한다. 문서를 수정해 현재 템플릿 구조를 적용할 때에만 새 템플릿 섹션 행을 추가하고, 저장 전에는 기존 문서 리비전이나 섹션 연결을 바꾸지 않는다.

## 태그와 문서 리비전 태그

### `tags`

`tags`는 월드 공용 태그 목록을 기록한다. 태그 이름은 수정하지 않으며, 이름을 바꾸려면 기존 태그를 삭제하고 새 태그를 만든다. 아래 표의 공통 컬럼 여덟 개도 함께 가진다.

| 컬럼 | 형식 | 필수 | 제약·설명 |
| --- | --- | --- | --- |
| `id` | UUID v7 | 예 | 기본 키 |
| `world_id` | UUID v7 | 예 | 소속 월드. `worlds.id`를 참조한다. |
| `tag_nm` | 문자열 | 예 | 태그 이름 |

`del_yn`이 `N`인 행만을 대상으로 같은 `world_id` 안에서 `tag_nm`이 중복될 수 없다. 태그를 삭제하면 현재 문서에서의 태그 노출과 검색 대상은 즉시 제외하되, 과거 문서 리비전의 태그 기록은 유지한다.

### `doc_rvs_tags`

`doc_rvs_tags`는 문서 리비전 시점의 태그 연결 스냅샷이다. 현재 문서의 태그는 `docs.now_doc_rvs_id`가 가리키는 리비전의 이 테이블 행 중, `tags`가 활성·미삭제 상태인 것만 사용한다. 아래 표의 공통 컬럼 여덟 개도 함께 가진다.

| 컬럼 | 형식 | 필수 | 제약·설명 |
| --- | --- | --- | --- |
| `id` | UUID v7 | 예 | 기본 키 |
| `doc_rvs_id` | UUID v7 | 예 | 소속 문서 리비전. `doc_rvss.id`를 참조한다. |
| `tag_id` | UUID v7 | 예 | 연결한 태그. `tags.id`를 참조한다. |

같은 `doc_rvs_id` 안에서 `tag_id`는 중복될 수 없다. `tag_id`는 문서가 속한 `world_id`와 같은 월드의 태그여야 한다. 태그 삭제 뒤에는 새 문서 리비전에 그 태그를 연결하지 않으며, 태그를 복구하면 삭제 후 저장으로 연결이 달라지지 않은 현재 문서에는 해당 태그가 다시 표시된다.

## 위키링크

| 컬럼 | 형식 | 필수 | 제약·설명 |

| `doc_rvs_sect_id` | UUID v7 | 예 | 위키링크가 있는 원본 문서 리비전 섹션. `doc_rvs_sects.id`를 참조한다. |
| `lnk_seq` | 정수 | 예 | 같은 섹션 본문 안에서의 위키링크 순서 |

같은 `doc_rvs_sect_id` 안에서 `lnk_seq`는 중복될 수 없다. `trgt_doc_id`는 원본 문서와 같은 월드에 속해야 한다. 현재 문서와 공개 문서는 대상 문서의 현재 이름을 표시하고, 과거 문서 리비전은 `trgt_indct_nm`, `trgt_doc_nm`을 사용한다. 대상 문서가 비공개 또는 삭제된 경우에는 이 연결을 지우지 않고 열람 시점에 각각 `비공개 문서`, `삭제됨`으로 표시한다.

## 관계 유형과 관계

### `rel_types`

`rel_types`는 시스템 기본 관계 유형과 월드 사용자 정의 관계 유형의 정의를 함께 기록한다. 시스템 기본 관계 유형 936개는 이 테이블의 `world_id` 없는 행으로 제공하고, 월드는 이를 복제하지 않고 참조한다. 아래 표의 공통 컬럼 여덟 개도 함께 가진다.

| 컬럼 | 형식 | 필수 | 제약·설명 |
| --- | --- | --- | --- |
| `id` | UUID v7 | 예 | 기본 키 |
| `world_id` | UUID v7 | 아니오 | 사용자 정의 관계 유형의 소속 월드. `worlds.id`를 참조한다. 비어 있으면 시스템 기본 관계 유형이다. |
| `rel_type_cd` | 문자열 | 예 | 변경할 수 없는 관계 유형 코드 |
| `rel_type_nm` | 문자열 | 예 | 관계 유형 이름 |

`world_id`가 비어 있으면 시스템 기본 관계 유형이고, 값이 있으면 해당 월드에서만 사용할 수 있는 사용자 정의 관계 유형이다. 시스템 기본 관계 유형은 수정·삭제할 수 없고 코드도 변경할 수 없다. 시스템 기본 관계 유형의 `rel_type_cd`는 서비스 전체에서 중복될 수 없고, 사용자 정의 관계 유형의 `rel_type_cd`는 같은 `world_id` 안에서 중복될 수 있다. 사용 중인 사용자 정의 관계 유형은 삭제하지 않고 비활성화만 허용하며, 참조가 없어진 경우에만 삭제할 수 있다.

### `world_rel_types`

`world_rel_types`는 월드가 참조하는 관계 유형과 월드별 활성 상태를 기록한다. 시스템 기본 관계 유형의 활성화·비활성화와 사용자 정의 관계 유형의 사용 상태를 이 테이블에서 관리한다. 아래 표의 공통 컬럼 여덟 개도 함께 가진다.

| 컬럼 | 형식 | 필수 | 제약·설명 |
| --- | --- | --- | --- |
| `id` | UUID v7 | 예 | 기본 키 |
| `world_id` | UUID v7 | 예 | 대상 월드. `worlds.id`를 참조한다. |
| `rel_type_id` | UUID v7 | 예 | 참조할 관계 유형 정의. `rel_types.id`를 참조한다. |

같은 `world_id` 안에서 `rel_type_id`는 중복될 수 없다. `rel_type_id`가 사용자 정의 관계 유형이면 그 유형의 `rel_types.world_id`는 이 행의 `world_id`와 같아야 한다. `use_yn`은 해당 월드에서 관계 유형을 새 관계에 사용할 수 있는지를 뜻한다. 비활성화하면 이 행을 참조하던 기존 관계도 소프트 딜리트로 끊고, 다시 활성화해도 끊긴 관계는 복구하지 않는다.

새 월드를 만들면 시스템 기본 관계 유형 936개를 모두 참조하는 `world_rel_types` 행을 `use_yn='Y'`로 함께 만든다.

### `rel_type_roles`

`rel_type_roles`는 관계 유형별 참여자 역할과 역할 반복 허용 규칙을 기록한다. 아래 표의 공통 컬럼 여덟 개도 함께 가진다.

| 컬럼 | 형식 | 필수 | 제약·설명 |
| --- | --- | --- | --- |
| `id` | UUID v7 | 예 | 기본 키 |
| `rel_type_id` | UUID v7 | 예 | 대상 관계 유형. `rel_types.id`를 참조한다. |
| `rel_role_cd` | 문자열 | 예 | 관계 유형 안에서 변경할 수 없는 참여자 역할 코드 |
| `rel_role_nm` | 문자열 | 예 | 참여자 역할 이름 |
| `rept_prm_yn` | 문자열(1) | 예 | 같은 역할을 여러 참여 문서에 반복할 수 있는지 여부. `Y` 또는 `N`만 허용한다. |

같은 `rel_type_id` 안에서 `rel_role_cd`와 `rel_role_nm`은 각각 중복될 수 없다. 한 번이라도 관계에 사용한 사용자 정의 관계 유형은 이 역할 구조를 변경할 수 없다.

### `rel_type_role_ctgrys`

`rel_type_role_ctgrys`는 참여자 역할별 허용 카테고리 정의를 기록한다. 기본 카테고리는 모든 프로젝트에서 같은 카테고리 정의를 참조하고, 사용자 정의 카테고리는 자신의 프로젝트 범위에서만 참조되므로 관계 유형이 월드 단위여도 두 경우를 함께 처리할 수 있다. 아래 표의 공통 컬럼 여덟 개도 함께 가진다.

| 컬럼 | 형식 | 필수 | 제약·설명 |
| --- | --- | --- | --- |
| `id` | UUID v7 | 예 | 기본 키 |
| `rel_type_role_id` | UUID v7 | 예 | 대상 참여자 역할. `rel_type_roles.id`를 참조한다. |
| `ctgry_id` | UUID v7 | 예 | 허용 카테고리 정의. `ctgrys.id`를 참조한다. |

같은 `rel_type_role_id` 안에서 `ctgry_id`는 중복될 수 없다. 시스템 기본 관계 유형의 역할은 시스템 기본 카테고리만 참조할 수 있다. 사용자 정의 관계 유형의 역할은 시스템 기본 카테고리 또는 같은 월드 프로젝트의 사용자 정의 카테고리를 참조할 수 있다.

`rels`는 실제로 만들어진 하나의 관계를 한 번만 기록한다. 보는 문서의 위치에 따라 정방향 또는 역방향으로 표시할 뿐, 반대 방향 관계를 별도로 만들지 않는다. 아래 표의 공통 컬럼 여덟 개도 함께 가진다.

| 컬럼 | 형식 | 필수 | 제약·설명 |

| `bgng_pstn` | 문자열 | 아니오 | 관계의 선택적 시작 시점. 창작물 안의 다양한 날짜 표기를 그대로 기록하므로 날짜·시간 형식으로 제한하지 않는다. |

## 관리자 초대·비밀번호 재설정·감사 이력·계정 탈퇴

### `admin_invits`

`admin_invits`는 월드 부관리자 초대의 대기 상태를 기록한다. 기존 계정 초대와 신규 계정 초대는 같은 행으로 처리하며, 수락 전에는 초대의 권한과 대상 프로젝트를 바꿀 수 없다. 아래 표의 공통 컬럼 여덟 개도 함께 가진다. 생성자와 생성 날짜·시간은 초대한 관리자와 발송 시각을 뜻한다.

| `id` | UUID v7 | 예 | 기본 키 |

| `invtd_admin_id` | UUID v7 | 아니오 | 이메일과 일치한 기존 초대 대상 계정. `admins.id`를 참조한다. 신규 계정 초대 또는 탈퇴 계정의 과거 초대 기록에서는 비워 둔다. |

대기 초대는 취소 또는 만료 전까지 한 이메일과 월드에 하나만 둘 수 있다. 이메일을 잃었거나 발송에 실패하면 같은 대기 초대를 재발송할 수 있으며, `invit_hash`, 상태, 권한, 대상 프로젝트, 만료 시각은 바꾸지 않는다. 수락하면 기존 계정은 기존 인증 정보를 유지하고, 신규 계정은 `admins` 행과 임시 비밀번호 상태를 만든다. 어느 경우든 초대 당시의 권한 스냅샷으로 부관리자 역할과 세부 허가를 만든다.

### `admin_invit_prmsn_ruls`

`admin_invit_prmsn_ruls`는 대기 초대에 포함한 프로젝트 범위별 세부 허가 스냅샷이다. 수락 시 해당 행을 같은 값의 `admin_prmsn_ruls` 행으로 반영한다. 아래 표의 공통 컬럼 여덟 개도 함께 가진다.

| `whdwl_stt_cd` | 문자열 | 예 | 진행, 완료 중 하나를 기록한다. 탈퇴 요청 직후에는 진행이다. |
| `expry_dt` | 날짜·시간 | 예 | `yyyy-MM-dd HH:mm:ss.sss` 형식의 데이터 내려받기 만료 시각. 탈퇴 요청 시각부터 7일 뒤다. |
| `dwnld_data_json` | JSON | 예 | 탈퇴 확정 시점의 내려받기 대상 데이터 스냅샷. Markdown·JSON ZIP은 이 값으로 생성한다. |

탈퇴 요청을 확정하면 즉시 로그인 세션과 일반 서비스 접근을 막는다. 부관리자가 있는 소유 월드는 탈퇴자가 지정한 부관리자를 즉시 관리자로 승격하고 `worlds.admin_id`를 이전한다. 만료 전까지는 탈퇴 안내 이메일의 전용 링크로만 여러 번 데이터를 내려받을 수 있다. 링크를 잃으면 같은 이메일로 재발송할 수 있으며, 재발송 시 `dwnld_hash`를 새 값으로 바꿔 기존 링크를 즉시 무효화한다. 내려받기에는 탈퇴 확정 시점에 탈퇴 계정이 소유한 월드 전체와 다른 월드에서 탈퇴 계정이 작성한 문서·관계만 포함하며, 다른 관리자가 소유한 공동 관리 월드 전체는 포함하지 않는다. 만료되면 `whdwl_stt_cd`를 완료로 바꾼다. 부관리자가 없는 소유 월드는 계정과 그 모든 하위 데이터를 소프트 딜리트가 아닌 완전 삭제한다. 다른 관리자의 월드에 남은 문서·관계는 유지하고, 해당 계정을 가리키는 공통 작성자·수정자·삭제자 참조는 비운다. 내부 운영 백업은 이 테이블의 사용자 데이터 복구 기능이 아니다.

### `admin_whdwl_world_scsns`

`admin_whdwl_world_scsns`는 탈퇴 계정이 소유한 월드별로 지정한 소유권 승계 부관리자를 기록한다. `scsn`은 공통 표준용어의 승계(`Succession`) 약어를 따른다. 아래 표의 공통 컬럼 여덟 개도 함께 가진다.

| 컬럼 | 형식 | 필수 | 제약·설명 |
| --- | --- | --- | --- |
| `id` | UUID v7 | 예 | 기본 키 |
| `admin_whdwl_req_id` | UUID v7 | 예 | 탈퇴 요청. `admin_whdwl_reqs.id`를 참조한다. |
| `world_id` | UUID v7 | 예 | 소유권을 이전할 월드. `worlds.id`를 참조한다. |
| `scsn_admin_id` | UUID v7 | 예 | 탈퇴자가 지정한 승계 부관리자. `admins.id`를 참조한다. |

같은 `admin_whdwl_req_id` 안에서 `world_id`는 중복될 수 없다. `world_id`는 탈퇴 계정이 소유한 월드여야 하고, `scsn_admin_id`는 해당 월드에 소속된 부관리자여야 한다. 탈퇴 확정 시 이 행을 기준으로 지정 부관리자를 관리자 역할로 승격하고 월드 소유권을 즉시 이전한다. 이때 대상 계정의 해당 월드 `admin_prmsn_ruls`는 관리자 전체 허가로 바꾸고 기존 부관리자 범위의 개별 허가 행은 제거한다.

내려받기 결과는 문서별 Markdown과 카테고리·태그·관계 등 구조 보존용 JSON을 하나의 ZIP으로 묶어 제공한다. 이 파일은 `dwnld_data_json`의 탈퇴 확정 시점 스냅샷으로 생성하므로, 그 뒤 다른 관리자가 데이터를 수정·삭제해도 내려받기 범위와 내용은 바뀌지 않는다. 파일 자체는 별도 테이블에 영구 보존하지 않는다.
