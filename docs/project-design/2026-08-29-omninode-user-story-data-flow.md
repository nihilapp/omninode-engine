# 옴니노드 유스케이스 데이터 플로우

> 분류: 프로젝트 설계
>
> 근거: `2026-08-30-omninode-use-cases.md`, `2026-08-29-omninode-user-stories.md`, `2026-08-29-omninode-requirements-decisions.md`
>
> 범위: 사용자 스토리가 읽고 생성·변경·보존하는 데이터를 정리한다. 테이블·컬럼·API 설계는 포함하지 않는다.

## 공통 데이터 원칙

- 모든 데이터는 월드 또는 프로젝트 범위를 명확히 가진다. 월드 밖 문서는 위키링크 대상으로 선택할 수 없다.
- 현재 상태와 과거 상태를 분리한다. 문서·템플릿은 리비전으로, 권한·관계 변경은 감사 이력으로 과거를 보존한다.
- 내부 식별자와 사람이 읽는 이름을 분리한다. 참조용 내부 코드와 문서 대상 ID는 변경하지 않는다.
- 뷰어·관리자 구분과 무관하게 프론트엔드 라우트의 월드·프로젝트 범위는 같은 공개 슬러그로 식별하며, 내부 UUID는 라우트에 노출하지 않는다.
- 계정 외 데이터는 소프트 딜리트로 보존한다. 계정은 탈퇴 요청 즉시 일반 서비스 접근을 막고, 7일 동안 자신이 만든 데이터를 내려받을 수 있게 한다. 부관리자가 없는 소유 월드는 계정과 함께 완전 삭제하고, 부관리자가 있는 소유 월드는 탈퇴 확정 즉시 탈퇴자가 지정한 부관리자에게 소유권을 넘겨 유지한다.
- 공개 데이터는 관리자가 선택한 공개 문서 리비전만 사용한다. 비공개·삭제 상태는 뷰어에게 접근 가능한 데이터 범위를 제한한다.

## 데이터 플로우

### DF-01. 관리자 계정과 월드 관리 권한

> 대응: UC-01, UC-04, UC-05 / US-01, US-02, US-09, US-14, US-15

- **주체와 시작 조건:** 운영자가 관리자 권한 요청을 승인하거나 계정의 월드 관리 권한을 변경한다. 계정 소유자는 비밀번호 재설정 또는 탈퇴를 요청할 수 있다.
- **읽기·검증:** 계정 존재 여부, 운영자 권한, 계정의 현재 역할과 소유 월드를 확인한다. 탈퇴 계정이 소유한 각 월드의 부관리자 목록과 탈퇴자가 지정한 승계 대상을 확인한다.
- **생성·변경·보존 데이터:** 새 관리자 계정에는 이메일·표시 정보·임시 비밀번호 상태를 만들고, 월드 관리 권한을 계정에 연결한다. 비밀번호 재설정 요청에는 만료 시각과 실제 변경 완료 상태를 기록한다. 계정 소유자가 다시 요청하면 새 요청을 만들고 기존 대기 요청을 무효화한다. 탈퇴 요청에는 이메일 전용 내려받기 링크의 검증값과 7일의 데이터 내려받기 만료 시각, 탈퇴 확정 시점의 내려받기 대상 데이터 스냅샷, 월드별 지정 승계 대상을 기록한다. 승계 대상은 관리자 역할과 해당 월드의 전체 허가를 받고, 기존 부관리자 범위의 개별 허가는 제거한다. 내려받기 ZIP은 이 스냅샷에서 문서별 Markdown과 카테고리·태그·관계 등 구조 보존용 JSON으로 구성한다.
- **결과와 후속 상태:** 권한은 즉시 적용한다. 비밀번호 재설정 링크는 발송 뒤 24시간 동안, 실제 비밀번호 변경이 완료되기 전까지 반복 접근할 수 있고, 변경 완료 시 즉시 사용할 수 없다. 새 비밀번호 재설정을 요청하면 새 링크만 유효하며 기존 대기 링크는 즉시 무효화한다. 탈퇴 요청을 확정하면 즉시 로그아웃과 일반 서비스 접근 차단을 적용하고, 부관리자가 있는 소유 월드는 지정 부관리자를 관리자로 승격해 소유권을 이전한다. 7일 동안은 탈퇴 안내 이메일의 전용 링크로만 탈퇴 확정 시점의 소유 월드 전체와 다른 월드에서 본인이 작성한 문서·관계를 반복해 내려받을 수 있다. 링크를 잃으면 같은 이메일로 재발송할 수 있고, 재발송 즉시 기존 링크는 무효화한다. 다른 관리자가 소유한 공동 관리 월드 전체는 내려받을 수 없다. 부관리자가 없는 소유 월드는 7일 뒤 계정과 함께 완전 삭제한다. 다른 관리자의 월드에 남은 문서·관계는 유지하고, 탈퇴 계정의 권한·소속·로그인 정보만 제거한다.

서비스 최초 설치 시에는 최초 운영자 계정을 직접 생성한다. 이 한 계정만 생성자 계정이 없어 `creatr_id`를 비워 둘 수 있고, `admins`에 시스템용 가상 계정을 만들지 않는다. 이후 생성되는 모든 데이터에는 실제 로그인 관리자 ID를 생성자로 기록한다.

### DF-02. 부관리자 초대와 권한 위임

> 대응: UC-02, UC-03, UC-25 / US-03 ~ US-08, US-10 ~ US-13

- **주체와 시작 조건:** 관리자 또는 운영자가 월드에 부관리자를 초대하거나 권한·소속을 변경한다.
- **읽기·검증:** 초대 이메일과 일치하는 기존 계정, 초대 권한, 대상 프로젝트와 부여 가능한 세부 권한을 확인한다.
- **생성·변경·보존 데이터:** 대기 초대에는 표시 이름·이메일·대상 월드·프로젝트·권한·7일 만료를 보존한다. 신규 계정이면 계정과 임시 비밀번호 상태를 만들고, 기존 계정이면 기존 인증 정보를 유지한다. 권한·소속 변경 전후와 수행자는 감사 이력으로 남긴다.
- **결과와 후속 상태:** 초대 수락 시 최신이 아닌 발송 당시 권한과 대상 프로젝트로 소속을 만든다. 대기 초대는 취소만 가능하다. 이메일을 잃었거나 발송에 실패하면 같은 대기 초대를 상태·권한·대상 프로젝트·수락 링크 변경 없이 재발송할 수 있다. 권한 변경·소속 해제는 다음 작업부터 즉시 반영된다.

### DF-03. 월드와 프로젝트의 생성·삭제

> 대응: UC-06 ~ UC-08 / US-16 ~ US-20

- **주체와 시작 조건:** 권한 있는 관리자가 월드·프로젝트를 만들거나 삭제·복구한다.
- **읽기·검증:** 월드 이름은 같은 관리자가 만든 월드 안에서, 프로젝트 이름은 같은 월드 안에서 중복을 검사한다. 생성자가 직접 입력한 공개 주소용 월드 슬러그는 서비스 전체에서, 프로젝트 슬러그는 같은 월드 안에서 영문 대소문자를 구분하지 않고 중복을 검사한다. 슬러그에는 한글, 영문 대소문자, 숫자, 하이픈만 허용한다. 같은 이름의 삭제 항목도 확인한다.
- **생성·변경·보존 데이터:** 새 월드·프로젝트에는 생성자가 입력한 공개 주소용 변경 불가 슬러그와 범위·소유자를 만들고 기본 관계 유형·카테고리·템플릿 활성 상태를 만든다. 삭제는 상위 항목의 삭제 상태만 바꾼다.
- **결과와 후속 상태:** 삭제된 같은 이름 항목이 있으면 복구 또는 새 생성을 선택한다. 월드·프로젝트 복구 시 하위 데이터는 기존 상태로 다시 접근 가능해진다.

### DF-04. 카테고리와 템플릿 구성

> 대응: UC-09 ~ UC-13, UC-17 / US-21 ~ US-35, US-68

- **주체와 시작 조건:** 카테고리 관리 권한이 있는 관리자가 카테고리 관리 페이지에서 대분류 카테고리에 템플릿을 연결·해제하거나 카테고리를 관리한다. 템플릿 관리 권한이 있는 관리자는 템플릿과 템플릿 섹션을 만들거나 수정·비활성화한다.
- **읽기·검증:** 카테고리 깊이(최대 3단계), 같은 부모 이름, 대분류의 템플릿 연결, 템플릿 이름·섹션 이름, 변경 불가 내부 코드를 확인한다.
- **생성·변경·보존 데이터:** 카테고리 트리와 순서, 대분류-템플릿 연결, 템플릿 섹션 구조, 템플릿 리비전 계보를 보존한다. 사용자 정의 카테고리는 대분류로 만들거나 시스템 기본 카테고리 또는 같은 프로젝트의 사용자 정의 카테고리 아래에 둘 수 있다. 문서 리비전에는 적용 당시의 템플릿 리비전과 이미 연결된 섹션 코드 참조를 남긴다. 현재 적용 중인 템플릿 리비전이 수정 또는 복원으로 바뀌면, 문서의 최신 문서 리비전이 참조하는 템플릿 리비전과 비교해 `템플릿 점검 필요` 운영 상태를 다시 계산한다.
- **결과와 후속 상태:** 템플릿이 없는 대분류에서는 문서를 만들 수 없다. 템플릿을 수정해도 기존 문서 리비전과 공개본은 바뀌지 않는다. 다만 문서 수정 페이지는 최신 템플릿 구조로 렌더링한다. 이때 새 템플릿 섹션은 저장 전까지 문서와 연결하지 않으며, 저장하면 새 문서 리비전에 최신 템플릿 구조와 새 섹션 연결을 함께 기록한다. `템플릿 점검 필요` 문서는 문서 관리 목록에서 식별할 수 있으나, 이 표시만으로 문서를 자동 변경하거나 공개 상태를 바꾸지 않는다. 현재 적용 중인 템플릿 리비전을 연결한 새 문서 리비전이 저장되면 이 상태는 자동 해제하며, 별도의 점검 완료 동작은 두지 않는다. 사용 중인 템플릿·카테고리를 비활성화해도 기존 문서와 리비전은 유지한다. 템플릿 섹션은 삭제하지 않고 다른 구조는 새 템플릿으로 만든다.

### DF-05. 문서 작성과 문서 리비전

> 대응: UC-14 ~ UC-17 / US-36 ~ US-42, US-69

- **주체와 시작 조건:** 문서 권한을 가진 관리자가 문서를 만들거나 현재 문서 상태를 저장·복원한다.
- **읽기·검증:** 수정 페이지 진입 시 선택한 카테고리의 최신 템플릿 구조, 필수 `개요` 섹션, 문서의 현재 리비전과 적용 템플릿 리비전을 확인한다.
- **생성·변경·보존 데이터:** 문서 생성 즉시 빈 첫 리비전을 만든다. 사용자가 `저장`할 때마다만 섹션별 본문, 카테고리, 태그, 세계관 안의 시작·종료 시점, 연결 템플릿, 위키링크, 이전 문서 리비전과 당시 템플릿 리비전을 함께 보존한다. 시작·종료 시점은 세계관마다 표기 방식이 달라 각각 비울 수 있는 문자열이다. 이름 변경은 일반 문서 수정이 아닌 문서 관리 흐름에서만 수행하고, 변경 상태는 새 문서 리비전으로 보존한다. 공개 반영과 비공개 전환은 문서의 현재 공개 상태와 공개할 리비전 선택만 바꾸며 새 문서 리비전을 만들지 않는다. 관계는 별도 데이터로 관리하므로 문서 리비전에 포함하지 않는다. 수정 페이지에서 새 템플릿 섹션이 보이더라도 저장 전에는 문서 리비전이나 신규 섹션 연결을 만들지 않는다. 첫 버전에는 자동 임시 초안 데이터를 만들지 않는다.
- **결과와 후속 상태:** 과거 리비전 복원만으로 새 리비전은 만들지 않는다. 복원 뒤 저장하면 복원한 리비전을 이전 리비전으로 하는 새 리비전을 만든다. 문서 리비전을 복원해도 관계의 현재 참여·수정·삭제 상태는 바뀌지 않는다. 새 선택 섹션은 기존 문서가 수정 페이지에서 저장될 때 연결된다. 읽기·공개 화면은 각각 현재 문서와 공개 문서 리비전에 이미 연결된 템플릿 구조만 렌더링한다. 저장하지 않은 입력 내용은 보존하지 않는다.

### DF-06. 문서 이동·이름·위키링크

> 대응: UC-13, UC-18 ~ UC-20 / US-26 ~ US-29, US-43 ~ US-48

- **주체와 시작 조건:** 관리자가 문서를 다른 카테고리로 옮기거나, 이름을 관리 페이지에서 바꾸거나, 문서를 삭제·복구한다.
- **읽기·검증:** 대상 카테고리의 템플릿, 기존 섹션의 유지·삭제 선택, 동명 표시 이름과 괄호 구분 표기, 최대 3개 구간의 문서상 이름, 같은 월드 대상 문서를 확인한다. 문서상 이름의 슬래시 구분은 폴더 구조로 해석하지 않는다.
- **생성·변경·보존 데이터:** 문서 이동 결과와 문서 관리 흐름에서의 이름 변경 결과는 각각 새 문서 리비전으로 남긴다. 위키링크는 표시 문자열과 대상 문서 ID를 함께 보존하며, 이 연결은 각 문서 리비전에 귀속한다. 문서 삭제 시 리비전·태그·관계·링크 연결을 보존한다.
- **결과와 후속 상태:** 과거 리비전과 공개본은 당시 저장된 링크 대상 문서를 유지한다. 링크 대상의 현재 상태가 비공개 또는 삭제이면 열람 시점에 각각 `비공개 문서`, `삭제됨`으로 표시한다. 다른 템플릿 카테고리로 이동하면 관리자 선택에 따라 기존 섹션을 추가 섹션으로 남기거나 삭제한다. 삭제 문서는 `삭제됨`으로 표시되고, 복구하면 이전 연결을 함께 복구한다. 카테고리 트리 자체를 다른 상위 카테고리 아래로 이동하면 영향 문서·템플릿 연결·관계를 저장된 점검 상태로 전환한다. 영향 문서는 즉시 비공개가 되고, 관리자가 각 대상을 직접 완료 처리하기 전에는 다시 공개할 수 없다.

### DF-07. 태그

> 대응: UC-21 / US-49 ~ US-52, US-70

- **주체와 시작 조건:** 문서 작성·수정 중 관리자가 태그를 연결·해제하거나 새 태그를 입력한다. 관리자·운영자는 태그를 삭제·복구한다.
- **읽기·검증:** 월드 범위의 태그 이름 중복과 문서 수정 권한을 확인한다.
- **생성·변경·보존 데이터:** 새 태그는 월드 공용 태그 목록에 만들고 문서의 현재 태그 연결에 반영한다. 태그 삭제 시 현재 문서 연결을 자동 해제하되 과거 문서 리비전의 태그 기록은 보존한다.
- **결과와 후속 상태:** 삭제 태그는 과거 리비전의 이력으로만 남고, 해당 리비전이 공개되어 있더라도 뷰어 화면과 공개 문서 검색에서는 제외한다. 태그를 복구하면 자동 해제했던 문서 연결도 함께 복구한다. 태그 이름은 수정하지 않고 삭제 후 새 태그를 만든다.

### DF-08. 관계 유형과 관계 인스턴스

> 대응: UC-22 / US-53 ~ US-60

- **주체와 시작 조건:** 관계 관리 권한이 있는 관리자 또는 운영자가 월드 관계 유형을 활성화·비활성화하거나, 사용자 정의 관계 유형과 실제 관계를 만들고 수정·삭제한다.
- **읽기·검증:** 관계 유형의 활성 상태, 참여자 역할별 허용 카테고리, 역할 반복 가능 여부, 2~4개 참여 문서, 동일한 기존 관계를 확인한다.
- **생성·변경·보존 데이터:** 관계 유형에는 역할·허용 카테고리·반복 규칙을 보존한다. 관계 인스턴스에는 유형, 참여 문서와 역할, 선택적 창작물 시점 문자열, 설명, 관련 문서 링크를 보존한다. 관계 변경은 문서 리비전과 분리된 감사 이력으로 남긴다.
- **결과와 후속 상태:** 비활성화한 유형의 관계는 끊긴 소프트 딜리트 기록으로 남고 복구하지 않는다. 사용된 사용자 정의 관계 유형의 구조는 바꾸지 않으며, 다른 구조는 새 유형으로 만든다.

### DF-09. 공개 반영과 뷰어 열람

> 대응: UC-23, UC-24 / US-61 ~ US-67, US-70, US-71

- **주체와 시작 조건:** 관리자가 문서 리비전을 공개·갱신·비공개 처리하거나, 뷰어가 공개 문서를 검색·열람한다.
- **읽기·검증:** 공개할 문서 리비전, 그 리비전의 템플릿 리비전, 필수 섹션 내용, 공개 대상의 비공개·삭제 연결을 확인한다. 주소로 열람할 때에는 UUID와 별도로 관리하는 월드·프로젝트 슬러그와 문서상 이름이 현재 공개 문서를 가리키는지 확인한다.
- **생성·변경·보존 데이터:** 문서의 현재 공개 상태와 선택된 공개 문서 리비전을 보존한다. 기존 공개 리비전 정보는 비공개 뒤에도 보존한다.
- **결과와 후속 상태:** 뷰어는 모든 월드의 공개 문서만 이름·활성 태그·섹션 본문으로 검색하거나 `/월드코드/프로젝트코드/docs/문서이름` 주소로 연다. 문서 이름은 `docs` 뒤 최대 3개 경로 구간으로 표현하며, 이는 폴더가 아니다. 문서상 이름 변경 전의 주소는 별도 보존·리다이렉트 없이 404로 처리한다. 삭제 태그는 과거 공개 문서 리비전에 기록되어 있어도 표시하거나 검색하지 않는다. 비공개 문서는 `비공개 문서`, 삭제 문서는 `삭제됨`으로 제한해 표시하고, 리비전 이력은 노출하지 않는다.

## 데이터 스키마 구상에 필요한 데이터 묶음

- **식별과 범위:** 계정, 월드, 프로젝트, 카테고리, 문서, 템플릿, 태그, 관계 유형, 관계 인스턴스
- **권한과 초대:** 월드 소유, 월드 소속, 세부 권한, 대기 초대, 계정 인증 상태, 권한 감사 이력
- **구조와 이력:** 템플릿 섹션과 코드, 템플릿 리비전, 문서 리비전, 문서 섹션 본문, 공개본 선택
- **연결:** 카테고리-템플릿 연결, 문서-태그 연결, 위키링크 대상, 관계 참여자와 역할, 역링크
- **운영 상태:** 활성·비활성, 삭제·복구, 카테고리 이동 점검 필요·점검 완료, 템플릿 점검 필요, 공개·비공개, 비밀번호 재설정 링크 만료·완료, 계정 탈퇴 접근 차단·탈퇴 확정 시점 데이터 스냅샷·데이터 내려받기 기간
