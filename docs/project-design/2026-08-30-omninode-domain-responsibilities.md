# 옴니노드 도메인 책임 정의

> 분류: 프로젝트 설계
>
> 근거: 1차 기획, 사용자 스토리, 유스케이스, 데이터 플로우, 데이터 스키마의 확정 정책
>
> 범위: 각 도메인이 소유하는 개념·상태·행동과 다른 도메인 사이의 책임 경계를 정의한다. 화면, API, ORM, DDL은 포함하지 않는다.

## 공통 원칙

- 한 도메인은 자신이 소유한 상태의 생성·변경·보존 규칙을 책임진다.
- 다른 도메인의 데이터를 직접 바꾸기보다, 확정된 참조·상태 전이 규칙을 통해 영향을 전달한다.
- 공통 소프트 딜리트와 감사 컬럼은 모든 도메인에 적용하는 횡단 정책이며, 별도 업무 도메인이 아니다.
- 계정 탈퇴는 일반 소프트 딜리트의 예외다. 계정·소유 월드의 완전 삭제와 데이터 내려받기 범위는 계정·권한 도메인이 책임진다.

## 도메인 책임

| 도메인 | 소유 개념·상태 | 책임 행동 | 다른 도메인과의 경계 |
| --- | --- | --- | --- |
| 계정·인증 | 로그인 계정, 비밀번호, 임시 비밀번호 상태, 비밀번호 재설정, 탈퇴·데이터 내려받기 | 로그인 가능 상태를 관리하고, 비밀번호 변경·재설정·탈퇴와 탈퇴 뒤 7일 내려받기를 처리한다. | 역할·권한과 초대의 범위 판단은 권한·소속 도메인이 맡는다. 탈퇴가 다른 도메인의 데이터를 지우거나 소유권을 바꿔야 할 때만 확정된 탈퇴 규칙에 따라 영향을 요청한다. |
| 권한·소속 | 운영자·관리자·부관리자 역할, 월드·프로젝트 범위별 24개 허가, 부관리자 초대, 권한 감사 이력 | 누가 어느 월드·프로젝트에서 어떤 행동을 할 수 있는지 판단하고, 초대·수락·권한 변경·소속 해제의 이력을 보존한다. | 각 업무 도메인은 행동을 실행하기 전에 이 도메인의 허가 판단을 사용한다. 역할만으로 권한을 우회하지 않는다. |
| 월드·프로젝트 | 월드, 프로젝트, 소유자, 공개 주소용 슬러그, 기본 데이터 활성 시작 상태 | 창작 세계관과 작품 범위를 만들고, 소유권·삭제·복구·슬러그 범위 규칙을 관리한다. | 카테고리·템플릿·문서·태그·관계는 월드 또는 프로젝트 범위에 소속된다. 월드·프로젝트 삭제는 하위 데이터의 자체 삭제 상태를 바꾸지 않고 접근 범위만 막는다. |
| 카테고리·템플릿 | 기본·사용자 정의 카테고리와 템플릿, 프로젝트별 사용 상태, 카테고리 트리, 템플릿 리비전·섹션 코드 | 문서 작성 구조를 강제할 카테고리·템플릿 연결과 섹션 구조·리비전·사용 중지 규칙을 관리한다. | 문서 도메인은 선택한 카테고리의 대분류 템플릿을 반드시 따른다. 카테고리 이동은 문서·관계의 점검 상태와 공개 중단에 영향을 주지만, 각 대상의 실제 점검 완료는 해당 도메인 규칙으로 처리한다. |
| 문서·리비전 | 문서 식별·이름·현재 리비전·공개 상태, 문서 리비전·섹션 본문·세계관 시점 | 섹션별 설정 내용을 보존하고, 카테고리·템플릿 적용, 리비전 계보, 복원, 이름 관리, 삭제·복구를 처리한다. | 태그·위키링크는 문서 리비전에 연결하지만 각각의 목록·대상 문서 상태는 태그·문서 연결 규칙을 따른다. 관계 인스턴스의 현재 상태는 문서 리비전에 포함하지 않는다. |
| 문서 연결 | 위키링크, 역링크, 문서상 이름과 대상 문서 ID의 연결 | 위키링크 문자열과 내부 대상 참조를 함께 보존하고, 이름 변경에도 연결이 유지되게 하며 역링크를 제공한다. | 대상 문서의 공개·삭제 여부는 문서·공개 도메인이 판단한다. 연결 도메인은 그 결과에 따라 `비공개 문서` 또는 `삭제됨` 표기를 적용한다. |
| 태그 | 월드 공용 태그 목록, 문서 리비전별 태그 연결, 태그 삭제·복구 상태 | 문서 작성·수정 중 태그를 연결하고 새 태그를 자동 추가하며, 관리자·운영자의 태그 목록 정리와 삭제·복구 결과를 관리한다. | 문서 도메인의 작성·수정 허가에는 태그 연결·해제·새 태그 추가가 포함된다. 태그 삭제는 현재 문서 노출·검색에는 영향을 주지만 과거 리비전 기록은 지우지 않는다. |
| 관계 | 기본·사용자 정의 관계 유형, 역할·허용 카테고리·반복 규칙, 관계 인스턴스·참여자·변경 이력 | 월드 안 2~4개 문서의 관계와 관계 유형을 관리하고, 중복 방지·비활성화에 따른 관계 종료·단순 이력을 처리한다. | 문서 도메인은 관계의 참여 상태를 리비전에 보존하거나 복원하지 않는다. 카테고리 이동으로 관계 구조가 영향받으면 점검 상태만 전환한다. |
| 공개·열람 | 문서의 공개 여부, 선택된 공개 리비전, 공개 검색·열람 가능 범위, 공개 주소 해석 | 뷰어에게 어떤 문서 리비전을 보일지 결정하고, 비공개·삭제 연결의 표기와 공개 검색 범위를 적용한다. | 문서 도메인이 보존한 리비전을 선택해 공개할 뿐 새 리비전을 만들지 않는다. 월드·프로젝트 슬러그와 문서상 이름은 주소 식별에 사용하고, 내부 UUID는 프론트엔드 라우트에 노출하지 않는다. |

## 책임 경계의 핵심 규칙

1. 문서의 내용·카테고리·템플릿·태그·세계관 시점은 문서 리비전으로 보존하지만, 관계 인스턴스의 현재 참여 상태는 관계 도메인에만 둔다.
2. 템플릿 변경은 기존 문서 리비전이나 공개본을 바꾸지 않는다. 문서가 수정·저장될 때 문서 도메인이 최신 템플릿 구조를 새 리비전에 적용한다.
3. 공개·비공개 전환은 공개·열람 도메인의 상태 변경이며, 문서 리비전을 새로 만들지 않는다.
4. 카테고리 이동의 영향 점검은 카테고리·템플릿 도메인이 시작하고, 문서·관계 도메인이 각자의 점검 상태와 공개 제한을 적용한다.
5. 부관리자의 허가 판단은 권한·소속 도메인이 담당한다. 문서 도메인의 태그 입력은 문서 허가로 판단하며, 태그 목록 정리는 별도 태그 관리 허가로 판단한다.
