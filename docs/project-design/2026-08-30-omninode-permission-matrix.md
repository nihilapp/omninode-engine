# 옴니노드 권한 매트릭스

> 분류: 프로젝트 설계
>
> 근거: 1차 기획의 관리자·권한 정책과 도메인 책임 정의
>
> 범위: 역할과 범위별 행동 허용 여부를 정의한다. 화면, API, 권한 체크 구현 방식은 포함하지 않는다.

## 공통 판단 원칙

- 실제 허가는 역할 이름만이 아니라 월드·프로젝트 범위별 24개 허가로 판단한다.
- 한 계정은 한 월드에서는 관리자 또는 부관리자 중 하나의 역할을 가지며, 다른 월드에서는 다른 역할을 가질 수 있다.
- 운영자는 전역 범위에서 모든 월드의 관리 행동을 수행한다.
- 관리자는 자신이 소유·관리하는 월드에서 전체 관리 행동을 수행한다.
- 부관리자는 초대 시 또는 이후 관리자가 부여한 프로젝트 범위 안에서만 허가받은 행동을 수행한다.
- 문서 작성·수정 허가에는 태그 연결·해제와 새 태그 자동 추가가 포함된다. 이는 태그 목록 관리 허가와 별개다.
- 공개 문서의 일반 뷰어는 계정을 만들지 않으며, 공개 열람 범위 밖의 데이터에 접근할 수 없다.

## 역할별 기본 범위

| 역할 | 기본 범위 | 범위 밖 동작 |
| --- | --- | --- |
| 뷰어 | 모든 월드·프로젝트의 공개 문서 | 비공개·삭제 문서와 관리 기능에 접근할 수 없다. |
| 운영자 | 전역 | 모든 월드의 관리와 운영자 전용 계정·권한 관리를 수행한다. |
| 관리자 | 자신이 소유·관리하는 월드 전체 | 다른 관리자의 월드에서는 부관리자 역할·허가가 있는 경우에만 해당 허가 범위로 작업한다. |
| 부관리자 | 관리자가 지정한 월드 또는 프로젝트 범위 | 지정되지 않은 프로젝트와 월드 관리 영역에는 접근할 수 없다. |

## 특수 권한 규칙

1. 카테고리와 템플릿을 연결·해제하는 행동은 템플릿 허가가 아니라 카테고리 허가로 판단한다.
2. 문서 공개 반영·비공개 전환과 리비전 복원은 문서 수정 허가로 판단한다.
3. 부관리자의 프로젝트 허가는 프로젝트 자체만 대상으로 하며, 카테고리·템플릿·문서·태그·관계 관리 허가를 자동으로 포함하지 않는다.
4. 부관리자의 태그 목록 관리과 관계 관리 허가는 항상 불가다. 문서 편집 안에서의 태그 입력은 예외적으로 문서 허가에 포함한다.
5. 사용 중인 사용자 정의 카테고리·템플릿·관계 유형의 삭제 가능 여부는 허가뿐 아니라 각 도메인의 참조·사용 상태 검증을 모두 통과해야 한다.
