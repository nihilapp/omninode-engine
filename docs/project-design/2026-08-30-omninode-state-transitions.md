# 옴니노드 상태 정의 및 전이

> 분류: 프로젝트 설계
>
> 근거: 확정 1차 기획, 사용자 스토리, 유스케이스, 데이터 플로우, 데이터 스키마, 도메인 책임·권한 매트릭스·검증 규칙·실패 조건
>
> 범위: 도메인별 최초 상태, 허용 전이, 전이 주체와 결과를 정의한다. 화면, API, DB 구현 방식은 포함하지 않는다.

## 공통 상태 모델

| 구분 | 상태 | 최초 상태 | 전이 규칙 |
| --- | --- | --- | --- |
| 사용 상태 | 사용, 사용 중지 | 새 데이터는 사용 | 사용 중지와 사용 전환은 해당 도메인이 허용한 항목에서만 가능하다. 사용 중지는 새 선택·새 연결·새 생성을 막지만, 기존 참조와 이력 자체를 지우지 않는다. |
| 삭제 상태 | 정상, 삭제 | 정상 | 모든 일반 업무 데이터는 소프트 딜리트를 사용한다. 삭제와 복구는 사용 상태를 바꾸지 않는다. |
| 상위 범위 접근 상태 | 접근 가능, 접근 차단 | 상위 월드·프로젝트가 정상일 때 접근 가능 | 월드 또는 프로젝트가 삭제되면 하위 데이터의 삭제 상태는 그대로 두고 일반 관리·열람 접근만 차단한다. 상위를 복구하면 하위 데이터도 각자의 삭제·사용 상태를 기준으로 다시 접근을 판단한다. |
| 계정 탈퇴 상태 | 일반 서비스 이용 가능, 탈퇴 진행, 탈퇴 완료 | 일반 서비스 이용 가능 | 계정 탈퇴는 일반 소프트 딜리트의 예외다. 탈퇴 진행 중에는 일반 서비스 접근이 즉시 차단되고, 7일 뒤 완전 삭제가 끝나면 탈퇴 완료가 된다. |

`use_yn`과 `del_yn`은 서로 다른 상태다. 예를 들어 삭제된 항목을 복구해도 이전의 사용·사용 중지 상태는 유지한다. 반대로 사용 중지된 항목을 삭제해도 사용 상태는 임의로 바꾸지 않는다.

## 상태값 목록

아래 목록은 현재 기획에서 허용한 **논리 상태값**이다. `*_stt_cd`의 실제 저장 코드값은 구현 시 공통표준용어를 대조해 별도로 정하며, 이 목록에 없는 상태를 임의로 추가하지 않는다.

| 상태 항목 | 적용 대상 | 허용 값 | 최초 값 | 비고 |
| --- | --- | --- | --- | --- |
| `use_yn` | 모든 테이블의 공통 상태 | `Y`(사용), `N`(사용 중지) | `Y` | 사용 중지가 정책으로 허용된 항목에서만 `N`으로 전환한다. |
| `del_yn` | 모든 테이블의 공통 상태 | `N`(정상), `Y`(삭제) | `N` | 계정 탈퇴에 따른 완전 삭제는 이 공통 상태의 예외다. |
| `tmpr_pswd_yn` | 관리자 계정 | `Y`(임시 비밀번호 변경 필요), `N`(일반 비밀번호) | 신규 계정은 `Y`, 기존 계정 초대 수락은 기존값 유지 | `Y`인 계정은 최초 로그인 뒤 비밀번호를 바꿔야 한다. |
| `invit_stt_cd` | 부관리자 초대 | 대기, 수락, 취소, 만료 | 대기 | 종료 상태인 수락·취소·만료에서는 다시 대기로 돌아가지 않는다. |
| `rst_stt_cd` | 비밀번호 재설정 요청 | 대기, 완료, 만료, 무효 | 대기 | 새 요청은 기존 대기 요청을 무효로 전환한다. |
| `whdwl_stt_cd` | 계정 탈퇴 요청 | 진행, 완료 | 진행 | 진행은 7일의 전용 데이터 내려받기 기간을 뜻한다. |
| `rls_yn` | 문서 | `Y`(공개), `N`(비공개) | `N` | `Y`일 때만 뷰어 검색·열람 대상이다. |
| `ctgry_mvmn_chck_yn` | 문서, 관계 | `Y`(점검 필요), `N`(점검 불필요) | `N` | 카테고리 이동 영향이 생기면 `Y`, 관리자가 직접 점검을 끝내면 `N`이다. |
| 템플릿 점검 표시 | 문서 관리 목록의 계산 상태 | 점검 필요, 점검 불필요 | 새 문서와 최신 템플릿 저장 문서는 점검 불필요 | 별도 상태값을 저장하지 않는다. 문서가 참조한 템플릿 리비전과 현재 템플릿 리비전을 비교해 계산한다. |
| 상위 범위 접근 표시 | 월드·프로젝트 하위 데이터의 계산 상태 | 접근 가능, 접근 차단 | 상위가 정상일 때 접근 가능 | 별도 상태값을 저장하지 않는다. 상위 월드·프로젝트의 삭제 상태로 계산한다. |
| 위키링크 표시 | 위키링크와 관계 설명의 대상 문서 | 일반 링크, 비공개 문서, 삭제됨 | 대상 문서 상태에 따라 계산 | 별도 상태값을 저장하지 않는다. 대상 문서의 공개·삭제 상태에 따라 표시한다. |

월드, 프로젝트, 카테고리, 템플릿, 태그, 관계 유형, 관계, 문서 리비전처럼 별도 `*_stt_cd`를 두지 않는 대상은 `use_yn`·`del_yn`, 리비전 포인터, 참조 상태를 조합해 현재 상태를 판단한다. 이 설계는 같은 대상을 단일 상태값 하나로 단순화해 리비전·삭제·사용 중지 상태가 서로 덮어쓰는 문제를 막는다.

## 계정·인증·초대

### 계정과 임시 비밀번호

| 상태 | 진입 | 허용 전이 | 결과 |
| --- | --- | --- | --- |
| 임시 비밀번호 변경 필요 | 운영자가 관리자 계정을 만들거나 신규 계정 초대가 수락됨 | 최초 로그인 뒤 비밀번호 변경 완료 → 일반 로그인 가능 | 임시 비밀번호가 이메일로 전달되며, 비밀번호 변경 전에는 일반 관리 행동을 할 수 없다. |
| 일반 로그인 가능 | 임시 비밀번호 변경 완료 또는 기존 계정 초대 수락 | 비밀번호 재설정 요청, 탈퇴 확정 | 계정의 역할·범위·세부 허가에 따라 일반 서비스를 이용할 수 있다. |
| 탈퇴 진행 | 계정 소유자가 탈퇴를 확정 | 7일 경과 → 탈퇴 완료 | 로그인 세션과 일반 서비스 접근을 즉시 차단한다. 전용 내려받기 링크로만 탈퇴 확정 시점의 데이터를 반복해 받을 수 있다. |
| 탈퇴 완료 | 탈퇴 진행 뒤 7일 경과 | 없음 | 계정과 탈퇴 계정이 소유한 대상 데이터는 완전 삭제한다. 다른 관리자의 월드에 남은 문서·관계는 유지하고, 해당 계정을 가리키는 작성자·수정자·삭제자 참조만 비운다. |

부관리자가 있는 소유 월드는 탈퇴 확정과 동시에 탈퇴자가 지정한 부관리자에게 소유권을 넘긴다. 부관리자가 없는 소유 월드는 계정 완전 삭제 시 함께 완전 삭제한다. 승계 대상이 필요한데 지정하지 않으면 탈퇴 진행으로 전이할 수 없다.

| 상태 | 진입 | 허용 전이 | 결과 |
| --- | --- | --- | --- |
| 대기 | 계정 소유자가 새 재설정을 요청 | 실제 비밀번호 변경 → 완료, 24시간 경과 → 만료, 새 요청 생성 → 무효 | 만료 전까지 같은 링크를 여러 번 열 수 있으며, 링크 열람만으로 상태는 바뀌지 않는다. |
| 완료 | 대기 요청으로 실제 비밀번호 변경 | 없음 | 해당 링크는 즉시 다시 사용할 수 없다. |
| 만료 | 대기 요청의 유효 시간 경과 | 없음 | 비밀번호를 바꾸지 않는다. 새 요청이 필요하다. |
| 무효 | 같은 계정의 새 재설정 요청이 생성됨 | 없음 | 이전 링크는 즉시 사용할 수 없다. |

### 부관리자 초대

| 상태 | 진입 | 허용 전이 | 결과 |
| --- | --- | --- | --- |
| 대기 | 관리자 또는 운영자가 월드 부관리자를 초대 | 수락, 취소, 만료 | 초대 당시의 월드·프로젝트 범위와 세부 허가를 스냅샷으로 보존한다. 재발송은 대기 상태와 스냅샷을 바꾸지 않는다. |
| 수락 | 유효한 대기 초대가 수락됨 | 없음 | 기존 계정은 인증 정보를 유지한 채 소속·허가가 생긴다. 신규 계정은 계정과 임시 비밀번호 변경 필요 상태가 함께 생긴다. |
| 취소 | 초대한 관리자 또는 운영자가 대기 초대를 취소 | 없음 | 수락할 수 없고, 권한을 바꾸려면 새 초대를 만들어야 한다. |
| 만료 | 대기 초대의 유효 기간 경과 | 없음 | 수락할 수 없다. 다시 초대하려면 새 초대를 만든다. |

## 권한·소속

| 대상 | 최초 상태 | 허용 전이 | 결과 |
| --- | --- | --- | --- |
| 운영자 역할 | 운영자가 계정을 만들고 부여 | 역할 부여, 해제 | 운영자는 모든 월드와 관리 기능을 관리할 수 있다. |
| 관리자 역할 | 운영자가 월드 관리 허가를 부여하거나, 탈퇴 승계로 부관리자가 승격 | 역할 부여, 해제, 승계에 따른 승격 | 월드 생성 허가를 받은 관리자는 새 월드를 만들 수 있다. 소속 월드에서의 역할과 다른 월드의 역할은 독립적으로 판단한다. |
| 부관리자 소속·허가 | 초대 수락 | 범위·세부 허가 변경, 소속 해제 | 부관리자는 월드 관리·부관리자 초대·관계 관리·태그 목록 관리 허가를 받을 수 없다. 프로젝트 관리 허가는 프로젝트 자체 관리에만 적용하고, 하위 카테고리·템플릿·문서·태그 목록의 관리는 각각의 별도 허가를 따른다. |

권한 변경은 즉시 다음 행동의 허가 판단에 반영한다. 과거에 수행한 행동·리비전·감사 이력을 되돌리지는 않는다.

## 월드·프로젝트

| 상태 | 진입 | 허용 전이 | 결과 |
| --- | --- | --- | --- |
| 정상 | 새 월드 또는 프로젝트 생성, 삭제 항목 복구 | 삭제 | 이름과 공개 주소용 코드는 생성 뒤 변경할 수 없다. 새 월드·프로젝트에는 기본 카테고리·템플릿·관계 유형 참조가 사용 상태로 준비된다. |
| 삭제 | 소프트 딜리트 | 복구 | 하위 데이터의 자체 삭제 상태를 바꾸지 않고 일반 관리·열람 접근을 차단한다. 같은 이름·코드로 새 항목을 만들려면 먼저 기존 삭제 항목 복구 여부를 확인한다. |

월드와 프로젝트의 삭제·복구는 관계된 하위 객체를 일괄 삭제·복구하는 전이가 아니다. 상위 객체가 복구된 뒤에도 하위 객체는 각자의 삭제·사용 상태를 유지한다.

## 카테고리·템플릿

### 카테고리와 프로젝트별 참조

| 대상 | 상태 | 허용 전이 | 결과 |
| --- | --- | --- | --- |
| 시스템 기본 카테고리 | 시스템 제공 | 프로젝트별 사용, 사용 중지 | 정의·코드·구조를 수정하거나 삭제할 수 없다. 프로젝트는 참조 상태만 바꿀 수 있다. |
| 사용자 정의 카테고리 | 정상 | 사용 중지, 삭제, 복구, 허용 범위 안의 이동·순서 변경 | 프로젝트 범위 또는 기본 카테고리 아래에 둘 수 있다. 이동으로 깊이가 3단계를 넘을 수 없다. 문서나 하위 카테고리가 남아 있으면 삭제로 전이할 수 없다. |
| 카테고리 이동 점검 | 점검 불필요 | 카테고리 이동 영향 발생 → 점검 필요, 관리자 점검 완료 → 점검 불필요 | 영향받은 문서와 관계는 점검 대상으로 기록한다. 문서는 즉시 비공개가 되고, 점검이 끝나기 전에는 다시 공개할 수 없다. |

카테고리의 사용 중지는 기존 문서의 분류를 바꾸지 않는다. 다만 새 문서 작성, 문서 이동, 새 관계·새 템플릿 연결의 대상으로는 사용할 수 없다.

| 사용자 정의 템플릿 | 정상 | 사용 중지, 삭제, 복구, 새 리비전 저장, 이전 리비전 적용 | 이미 사용 중이면 삭제할 수 없고 사용 중지만 가능하다. 참조가 없어야 삭제할 수 있다. |
| 템플릿 리비전 | 생성됨 | 새 리비전 저장, 이전 리비전 적용 | 생성·수정 저장 때 새 리비전이 생기고 직전 리비전 ID를 기록한다. 이전 리비전 적용만으로는 새 리비전을 만들지 않는다. |
| 문서의 템플릿 점검 필요 | 최신 템플릿이 바뀌고 기존 문서가 아직 저장되지 않음 | 문서 수정·저장으로 최신 구조 반영 → 점검 불필요 | 읽기·공개본은 기존 문서 리비전을 그대로 보인다. 수정 흐름에서는 최신 템플릿의 섹션 순서와 신규 섹션을 렌더링한다. 저장 전에는 신규 섹션 매핑과 문서 리비전이 생기지 않는다. |

템플릿의 필수 섹션은 삭제·이름 변경·순서 변경을 할 수 없다. 첫 필수 섹션 `개요` 위에는 어떤 섹션도 추가할 수 없다. 다른 구조가 필요하면 새 템플릿을 만든다.

## 문서·리비전·공개

### 문서와 문서 리비전

| 상태 | 진입 | 허용 전이 | 결과 |
| --- | --- | --- | --- |
| 편집 가능한 문서 | 새 문서 생성 또는 삭제 문서 복구 | 새 리비전 저장, 현재 리비전 변경, 이름 변경, 삭제 | 문서 생성 시 첫 문서 리비전이 자동으로 생긴다. 문서상 이름과 표시 이름은 문서 관리 흐름에서만 바꾼다. |
| 현재 리비전 | 문서 생성, 저장, 이전 리비전 적용 | 저장 → 새 현재 리비전, 이전 리비전 적용 → 과거 리비전으로 변경 | 저장은 문서 본문뿐 아니라 카테고리·템플릿·태그·세계관 시점 등 문서와 연결된 전체 상태를 새 리비전으로 보존한다. 이전 리비전 적용은 새 리비전을 만들지 않는다. 그 상태에서 저장하면 그 리비전을 기반으로 새 리비전이 생긴다. |
| 삭제 | 문서 소프트 딜리트 | 복구 | 공개·관리 일반 접근에서 제외한다. 이 문서를 참조한 공개 문서와 관계 설명에서는 `삭제됨`으로 표시하며, 연결 자체는 보존한다. 복구하면 문서와 연결 데이터의 복구 규칙을 적용한다. |

### 공개 상태

| 상태 | 진입 | 허용 전이 | 결과 |
| --- | --- | --- | --- |
| 비공개 | 새 문서 생성, 공개 해제, 카테고리 이동 영향 발생 | 필수 조건 충족 후 공개 | 뷰어 검색·열람에서 제외한다. 직접 접근은 허용하지 않는다. |
| 공개 | 관리자가 해당 문서의 리비전을 공개본으로 선택 | 공개 해제, 카테고리 이동 영향 발생 | 선택된 공개 리비전만 뷰어에게 보인다. 공개 전환은 문서 리비전을 새로 만들지 않는다. |

공개 중인 문서의 카테고리 이동이 문서·템플릿·관계 구조에 영향을 주면 즉시 비공개로 전환하고 점검 필요 상태를 남긴다. 관리자가 점검을 마치기 전에는 공개로 전이할 수 없다. 반면 템플릿 변경은 문서를 자동 비공개로 만들지 않는다. 기존 공개 리비전은 유지되고, 문서가 수정·저장될 때만 최신 템플릿 구조가 새 리비전에 반영된다.

문서상 이름을 바꾸면 이전 주소는 항상 404가 된다. 현재 이름을 사용하는 주소만 공개 문서를 찾을 수 있다. 문서상 이름은 슬래시를 포함할 수 있으나 `docs` 뒤 전체 구간은 최대 3단계이며, 이는 폴더·권한·카테고리 구조가 아니다.

## 태그·위키링크

| 대상 | 상태 | 허용 전이 | 결과 |
| --- | --- | --- | --- |
| 태그 | 정상 | 삭제, 복구 | 태그 이름은 수정하지 않는다. 문서 작성·수정 중 새 이름을 입력하면 활성 태그와 중복되지 않을 때 자동으로 생성한다. |
| 삭제 태그 | 삭제 | 복구 | 현재 문서의 태그 노출과 태그 검색에서는 제외한다. 과거 문서 리비전의 태그 기록은 보존한다. 복구 시 과거 기록만을 근거로 현재 문서에 자동 재연결하지 않는다. |
| 위키링크 | 연결 유지 | 대상 문서의 공개·삭제 상태 변화 | 저장 문자열과 대상 문서 내부 ID를 함께 보존한다. 대상이 비공개면 `비공개 문서`, 삭제면 `삭제됨`으로 표시한다. 대상 이름 변경에도 내부 연결은 유지한다. |

## 관계 유형·관계

### 관계 유형

| 대상 | 상태 | 허용 전이 | 결과 |
| --- | --- | --- | --- |
| 시스템 기본 관계 유형 | 시스템 제공 | 월드별 사용, 사용 중지 | 정의·코드·역할 구조를 수정하거나 삭제할 수 없다. 월드는 참조 상태만 바꿀 수 있다. |
| 사용자 정의 관계 유형 | 정상 | 월드별 사용, 사용 중지, 삭제, 복구 | 이미 관계에 사용한 유형은 구조를 변경할 수 없다. 사용 중이면 삭제할 수 없고, 참조가 없어야 삭제할 수 있다. |
| 월드별 관계 유형 참조 | 사용 | 사용 중지, 사용 | 사용 중지하면 기존 활성 관계를 즉시 종료한다. 다시 사용으로 바꿔도 종료된 관계는 복구하지 않는다. |

### 관계 인스턴스

| 상태 | 진입 | 허용 전이 | 결과 |
| --- | --- | --- | --- |
| 정상 | 참여 문서 2~4개와 역할 규칙을 만족해 생성 | 수정, 삭제, 카테고리 이동 영향에 따른 점검 필요 | 관계 생성·수정·삭제와 관계 유형 비활성화에 따른 종료는 단순 이력으로 남긴다. |
| 점검 필요 | 카테고리 이동으로 참여자 역할의 허용 카테고리 판단에 영향 발생 | 관리자 점검 완료 → 정상 | 관계 구조가 자동으로 바뀌지는 않는다. 관리자가 직접 현재 문서 카테고리와 역할 구조를 확인한다. |
| 삭제·종료 | 소프트 딜리트 또는 관계 유형 사용 중지 | 복구 불가 | 관계 유형 사용 중지로 종료된 관계는 유형을 다시 사용으로 바꾸어도 되살릴 수 없다. 필요한 관계는 새로 만든다. |

관계의 현재 참여 상태는 문서 리비전의 일부가 아니다. 문서 리비전을 적용하거나 복원해도 관계의 참여 상태는 바뀌지 않는다.

## 상태 전이 순서가 중요한 흐름

1. **카테고리 이동**: 카테고리 이동을 반영한다 → 영향받은 문서·관계에 점검 필요를 기록한다 → 공개 문서는 즉시 비공개로 전환한다 → 관리자가 문서·템플릿·관계 구조를 직접 점검한다 → 점검 완료한 대상만 점검 불필요로 전환한다 → 문서는 필수 조건을 충족한 경우에만 다시 공개할 수 있다.
2. **템플릿 변경 뒤 문서 저장**: 템플릿 리비전을 저장한다 → 기존 문서는 읽기·공개본을 유지하고 템플릿 점검 필요로 표시한다 → 문서 수정 흐름에서 최신 템플릿 구조를 렌더링한다 → 관리자가 저장하면 새 문서 리비전과 최신 템플릿 리비전 매핑을 남긴다.
3. **관계 유형 사용 중지**: 월드별 관계 유형 참조를 사용 중지로 바꾼다 → 해당 유형의 활성 관계를 즉시 삭제·종료 상태로 바꾸고 이력을 남긴다 → 관계 유형을 다시 사용으로 바꿔도 종료 관계는 복구하지 않는다.
4. **계정 탈퇴**: 승계가 필요한 월드의 대상 부관리자를 지정한다 → 탈퇴를 확정한다 → 승계 대상의 역할·소유권을 즉시 바꾸고 일반 서비스 접근을 막는다 → 탈퇴 확정 시점 스냅샷으로 7일 동안 반복 내려받기를 제공한다 → 기간 종료 뒤 계정과 완전 삭제 대상 데이터를 제거한다.

## 점검 결과

- 기존 기획의 상태 전이는 공통 사용·삭제 상태, 계정·초대·재설정·탈퇴, 권한·소속, 월드·프로젝트, 카테고리·템플릿, 문서·공개, 태그·위키링크, 관계 유형·관계에 모두 연결된다.
- 카테고리 이동과 템플릿 변경은 서로 다른 전이다. 전자는 영향 문서를 즉시 비공개·점검 필요로 만들며, 후자는 기존 읽기·공개본을 유지한 채 문서 수정·저장 시 최신 구조를 적용한다.
- 현재 확정된 정책 안에서 추가적인 비즈니스 결정이 필요한 상태 충돌은 발견하지 못했다.
