# 옴니노드 검증 규칙

> 분류: 프로젝트 설계
>
> 근거: 확정 1차 기획, 데이터 플로우, 데이터 스키마, 도메인 책임 정의, 권한 매트릭스
>
> 범위: 행동이 성공하기 위한 입력·범위·상태·중복·참조 정합성 조건을 정의한다. 화면·API·DB 제약 구현 방식은 포함하지 않는다.

## 공통 검증

1. 관리 행동은 먼저 로그인 상태, 역할, 월드·프로젝트 범위와 해당 생성·수정·삭제 허가를 확인한다.
2. 소프트 삭제된 상위 월드·프로젝트에 속한 데이터는 자체 삭제 상태와 무관하게 일반 관리 행동과 열람의 대상이 될 수 없다.
3. 사용 중지된 항목은 기존 참조를 렌더링할 수 있으나, 새 문서 작성·새 연결·새 선택의 대상으로 사용할 수 없다.
4. 새 항목이 같은 범위의 삭제 항목과 이름이 같으면 복구 또는 새 생성 의사를 확인한다. 복구를 선택하면 연결 데이터를 함께 복구한다.
5. 내부 코드와 월드·프로젝트 슬러그는 변경할 수 없다. 새 식별자는 정해진 범위의 중복 규칙을 통과해야 한다.

## 계정·권한·초대

| 행동 | 성공 조건 |
| --- | --- |
| 관리자 계정 생성·월드 관리 허가 부여 | 수행자는 운영자이며, 대상 계정·이메일의 중복과 전역 월드 관리 허가 상태가 유효하다. |
| 부관리자 초대 | 수행자는 대상 월드의 관리자 또는 운영자이며, 같은 월드·이메일의 대기 초대가 없다. 대상 프로젝트는 대상 월드에 속하고, 부관리자에게 금지된 허가는 포함하지 않는다. |
| 초대 수락 | 대기 초대가 취소·만료되지 않았고, 수락 링크가 유효하다. 기존 계정이면 초대 이메일과 일치해야 한다. |
| 권한·소속 변경 | 수행자는 관리자 또는 운영자이며, 대상 계정은 해당 월드의 부관리자다. 변경 값은 부관리자에게 허용되는 대상·프로젝트 범위 안이다. |
| 비밀번호 재설정 | 계정이 존재하고, 재설정 링크가 24시간 안의 대기 상태다. 새 요청은 기존 대기 요청을 무효화한다. |
| 탈퇴 확정 | 계정 소유자가 요청하며, 부관리자가 있는 소유 월드마다 승계할 부관리자 한 명이 지정돼 있다. |

## 월드·프로젝트

| 행동 | 성공 조건 |
| --- | --- |
| 월드 생성 | 수행자에게 월드 생성 허가가 있고, 같은 생성자가 만든 활성 월드와 월드 이름이 중복되지 않는다. 입력 슬러그는 한글·영문 대소문자·숫자·하이픈만 사용하며 영문 대소문자 비구분 전역 중복이 없다. |
| 프로젝트 생성 | 수행자에게 대상 월드의 프로젝트 생성 허가가 있고, 활성 프로젝트 이름과 프로젝트 슬러그가 해당 월드 안에서 중복되지 않는다. 슬러그 형식은 월드와 같다. |
| 월드·프로젝트 복구 | 대상이 삭제 상태이며, 복구 뒤 활성 항목과 이름·슬러그 중복이 발생하지 않는다. |
| 월드·프로젝트 삭제 | 수행자에게 삭제 허가가 있다. 삭제는 대상의 상태만 바꾸며 하위 데이터의 자체 삭제 상태를 바꾸지 않는다. |

## 카테고리·템플릿

| 행동 | 성공 조건 |
| --- | --- |
| 카테고리 생성·이동 | 수행자에게 카테고리 허가가 있고, 부모를 따라 계산한 깊이가 3단계를 넘지 않으며 같은 부모의 활성 카테고리 이름과 중복되지 않는다. 사용자 정의 카테고리는 대상 프로젝트 범위 또는 시스템 기본 카테고리 아래에서만 만든다. |
| 카테고리 삭제 | 수행자에게 삭제 허가가 있고, 문서와 하위 카테고리가 남아 있지 않다. 시스템 기본 카테고리는 삭제할 수 없다. |
| 카테고리 사용 중지 | 새 문서 작성·카테고리 변경·새 선택을 막되 기존 문서 분류는 유지한다. |
| 템플릿 연결 | 수행자에게 카테고리 허가가 있고, 대상은 대분류이며 해당 프로젝트에서 사용할 수 있는 템플릿이다. |
| 템플릿·섹션 변경 | 수행자에게 템플릿 허가가 있고, 첫 필수 섹션은 `개요`이며 그 위에 섹션을 둘 수 없다. 섹션 이름은 같은 템플릿에서 중복되지 않고 섹션 코드의 변경·삭제는 허용하지 않는다. |
| 템플릿 삭제·사용 중지 | 시스템 기본 템플릿은 삭제·수정할 수 없다. 사용 중인 사용자 정의 템플릿은 삭제할 수 없고 비활성화만 가능하며, 참조가 없어야 삭제할 수 있다. |

## 문서·태그·위키링크

| 행동 | 성공 조건 |
| --- | --- |
| 문서 생성 | 수행자에게 문서 생성 허가가 있고, 선택한 카테고리는 활성 상태이며 대분류에 활성 템플릿이 연결돼 있다. 같은 프로젝트의 활성 문서상 이름과 중복되지 않는다. |
| 문서 저장 | 수행자에게 문서 수정 허가가 있고, 적용 카테고리·템플릿·섹션 구조가 유효하다. 저장 시에만 새 리비전을 만들며, 현재 리비전을 변경하는 복원 자체는 새 리비전을 만들지 않는다. |
| 문서 이름 변경 | 일반 문서 수정이 아닌 문서 관리 흐름에서 수행한다. 문서상 이름의 슬래시는 최대 3개 구간이고, 같은 프로젝트 활성 문서상 이름과 중복되지 않는다. |
| 문서 이동 | 수행자에게 문서 수정 허가가 있고, 대상 카테고리는 활성 상태이며 템플릿을 연결한 대분류에 속한다. 다른 템플릿이면 기존 섹션마다 유지 또는 삭제 결정을 받아야 한다. |
| 문서 공개 반영 | 수행자에게 문서 수정 허가가 있고, 선택한 리비전이 해당 문서의 리비전이며 모든 필수 섹션 본문이 채워져 있다. 카테고리 이동 점검 필요 상태의 문서는 공개할 수 없다. |
| 위키링크 저장 | 대상 문서는 원본과 같은 월드에 속한다. 표시 문자열과 대상 내부 ID를 함께 보존한다. |
| 태그 연결·새 태그 입력 | 수행자에게 문서 작성 또는 수정 허가가 있고, 태그는 문서와 같은 월드에 속한다. 새 태그는 활성 월드 태그 이름과 중복되지 않을 때만 만든다. |
| 태그 삭제·복구 | 수행자는 관리자 또는 운영자다. 삭제 뒤 현재 문서 노출·검색에서는 제외하되 과거 리비전의 태그 기록은 유지한다. |

## 관계·공개 열람

| 행동 | 성공 조건 |
| --- | --- |
| 관계 유형·관계 관리 | 수행자는 관리자 또는 운영자이며, 관계 유형은 대상 월드에서 활성 상태다. |
| 관계 생성·수정 | 참여 문서는 2개 이상 4개 이하이고 모두 같은 월드에 속한다. 각 참여 문서는 역할별 허용 카테고리에 맞고, 역할 반복 규칙을 만족하며, 같은 유형·참여 문서·역할 구성의 활성 관계가 없다. |
| 관계 유형 비활성화 | 기존 관계는 즉시 종료·삭제 상태로 전환하며, 다시 활성화해도 종료된 관계를 복구하지 않는다. |
| 공개 문서 열람 | 문서가 공개 상태이고, 주소의 월드·프로젝트 슬러그와 문서상 이름이 현재 공개 문서를 가리킨다. 슬러그는 영문 대소문자를 구분하지 않고 해석한다. |
| 공개 문서 검색 | 문서상 이름·표시 이름·활성 태그·섹션 본문에서 공개 문서만 검색한다. |
