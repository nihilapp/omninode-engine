## 목표와 결정 요약

1. 입력·권한·상태 전이는 서비스가 먼저 검증하되, 저장 뒤에도 항상 참이어야 하는 데이터 불변식은 PostgreSQL 제약 또는 트리거가 다시 강제한다. 서비스 검증만으로 DB 무결성을 대신하지 않는다.
2. 단일 테이블의 필수값, 일반 키·외래 키, 일반 고유성, 단순 조건의 부분 고유 인덱스는 Prisma 모델에 선언한다. 이 프로젝트의 Prisma `7.9.1`에서는 `partialIndexes` 미리보기 기능을 켜고, 같은 행의 `del_yn`·`use_yn`·상태값만을 조건으로 쓰는 부분 고유 인덱스에 사용한다.
3. 행 안의 복합 조건, 대소문자 비구분 슬러그, 지연 외래 키, 다른 테이블을 함께 읽어야 하는 범위·계층·관계 참여 제약은 생성된 Prisma 마이그레이션에 추가하는 PostgreSQL SQL로 구현한다.
4. 프로젝트가 월드에 속하는 것처럼 두 외래 키 컬럼만으로 표현할 수 있는 범위 일치는 복합 외래 키로 강제한다. 상위 행의 범위나 현재 리비전처럼 다른 테이블을 따라가야 하는 조건은 트리거로 검증한다.
5. 카테고리 트리는 프로젝트 범위 안에서만 연결하고, 시스템 카테고리를 부모로 허용하며, 깊이 3단계와 순환 없음은 PostgreSQL 재귀 검사로 강제한다. 같은 프로젝트의 동시 이동은 트랜잭션 범위 잠금으로 직렬화한다.
6. 템플릿·문서와 최초 리비전의 순환 참조는 지연 외래 키와 하나의 서비스 트랜잭션으로 만든다. 커밋 시점에만 완전한 참조 상태를 허용한다.
7. 여러 행의 상태 전이, 권한, 활성·삭제 여부를 전제로 한 새 사용 가능 여부, 복구 선택, 영향 상태 갱신은 서비스 트랜잭션이 소유한다. DB 제약 위반은 최종 안전망이며 클라이언트가 자동 재시도하지 않는다.

## 책임 분리

| 계층 | 책임 | 이 설계에서 맡는 항목 |
| --- | --- | --- |
| Prisma 모델 | 현재 데이터 구조를 읽고 쓰기 위한 기본 선언 | UUID v7 키, 필수·선택 컬럼, 일반 외래 키, 일반 고유 키, 복합 고유 키, 같은 행 조건의 부분 고유 인덱스 |
| PostgreSQL 마이그레이션 SQL | Prisma가 표현하지 못하거나 DB에 직접 남아야 하는 불변식 | `Y`·`N` 값 검사, 행 안의 범위 조합 검사, 대소문자 비구분 부분 고유 인덱스, 지연 FK, 범위·계층·관계 카디널리티 트리거 |
| 서비스 트랜잭션 | 사용자 행동의 권한·상태·순서와 여러 행의 원자적 변경 | 생성 전 활성 상태·권한 검사, 삭제 항목 복구 또는 새 생성 선택, 만료·공개·이동 영향 처리, 트리거 오류의 공통 오류 응답 변환 |

`CHECK`에는 같은 새 행의 컬럼만 넣는다. 다른 행이나 다른 테이블을 읽는 조건을 `CHECK` 함수로 우회해 넣지 않는다. PostgreSQL은 그런 조건을 지속적으로 보장하지 않으므로, 가능한 복합 FK·고유 인덱스를 먼저 쓰고 그것으로 표현할 수 없는 경우에만 트리거를 사용한다.

## 소프트 삭제와 고유성

### 공통 원칙

1. 제품 스키마가 `del_yn = 'N'`인 행만 중복 검사 대상으로 명시한 경우에만 부분 고유 인덱스를 둔다. `use_yn = 'N'`은 삭제와 다른 상태이므로, 제품 규칙이 활성 행만을 대상으로 정한 경우에만 조건에 추가한다.
2. 삭제된 행과 같은 이름·슬러그를 새로 만들 수 있는 범위에서는, 새 행이 존재하는 동안 기존 삭제 행을 복구할 수 없다. 서비스는 복구 전 충돌을 안내하고, DB의 부분 고유 인덱스는 동시 요청에서도 복구 충돌을 막는다.
3. 코드·리비전·영속 섹션 코드처럼 삭제 뒤에도 과거 참조를 안정적으로 유지해야 하는 식별자는 부분 고유 인덱스로 완화하지 않는다. 제품 스키마가 정한 전체 고유성을 유지한다.
4. 모든 조회·갱신은 고유 인덱스의 존재만 믿지 않고, 자신의 목적에 맞는 `del_yn`·`use_yn`·상위 범위 상태 조건을 명시한다. 부분 인덱스는 접근 제어 또는 목록 필터를 대체하지 않는다.

### Prisma 부분 고유 인덱스 대상

| 대상 | 고유 범위 | 조건 | 근거 |
| --- | --- | --- | --- |
| `admins.eml` | 이메일 | `use_yn = 'Y' AND del_yn = 'N'` | 활성·미삭제 로그인 이메일만 중복 불가 |
| `admin_roles` | 운영자: `admin_id`, 월드 역할: `admin_id + world_id` | 활성·미삭제이며 역할·월드 조합이 각각 유효 | 계정의 운영자 역할 하나, 같은 월드 역할 하나 |
| `admin_prmsn_ruls` | 전역·월드·프로젝트별 허가 범위 | 활성·미삭제이며 각 범위 조합이 유효 | 가장 좁은 범위 판정의 기반 행 하나 |
| `admin_ssns` | `admin_id` | `del_yn = 'N' AND ssn_stt_cd = 'VALID'` | 계정별 유효 전역 세션 하나 |
| `worlds` | 생성자·이름, 슬러그 | `del_yn = 'N'` | 삭제된 월드와 동일한 이름·슬러그의 새 생성 허용 |
| `prjs` | 월드·이름, 월드·슬러그 | `del_yn = 'N'` | 삭제된 프로젝트와 동일한 이름·슬러그의 새 생성 허용 |
| `ctgrys` | 같은 프로젝트·부모 아래 이름 | `del_yn = 'N'` | 삭제된 동위 카테고리 이름은 새로 사용 가능 |
| `tmplts` | 같은 프로젝트의 템플릿 이름 | `del_yn = 'N'` | 삭제된 사용자 정의 템플릿 이름은 새로 사용 가능 |
| `docs` | 프로젝트·문서상 이름 | `del_yn = 'N'` | 삭제 문서와 같은 이름의 새 생성 또는 복구 선택 |
| `tags` | 월드·태그 이름 | `del_yn = 'N'` | 삭제된 태그 이름은 새로 사용 가능 |
| `rels` | 월드 관계 유형·정규화 참여자 해시 | `del_yn = 'N'` | 종료된 관계는 새 관계의 중복 판정에서 제외 |
| `admin_invits` | 월드·이메일 | 대기·미삭제 상태 | 취소·만료 전 대기 초대 하나 |
| `admin_pswd_rst_reqs` | `admin_id` | 대기·미삭제 상태 | 계정별 대기 비밀번호 재설정 요청 하나 |

`admin_ssn_clnts.resh_tkn_hash`, 영속 템플릿 섹션 코드, 시스템·사용자 정의 카테고리 코드, 템플릿 코드, 리비전 순번, 리비전 내부 섹션 코드·순번, 문서 리비전 내부 태그·링크 순번처럼 스키마가 전체 고유성을 정한 값은 일반 `@unique` 또는 `@@unique`로 선언한다.

### 공개 슬러그

`world_cd`, `prj_cd`는 영문 대소문자를 구분하지 않는 공개 주소 식별자다. 서비스는 입력을 소문자 정규화해 저장하고, PostgreSQL에는 `lower(...)`를 기준으로 한 부분 고유 인덱스를 추가한다. 인덱스 조건은 모두 `del_yn = 'N'`이다. 이는 ORM의 일반 문자열 고유성만으로는 대소문자 차이와 삭제 후 재사용을 동시에 보장할 수 없기 때문이다.

이 규칙에 맞춰 데이터 스키마도 삭제된 월드·프로젝트와 같은 슬러그의 새 생성 및 복구 충돌을 명시한다. URL 해석은 정규화한 슬러그로만 찾는다.

## 범위 참조 강제

### 복합 외래 키로 표현하는 범위

`prjs`에는 `id + world_id` 복합 고유 키를 함께 두고, 아래 참조는 두 컬럼을 함께 외래 키로 연결한다.

| 참조 행 | 강제할 조건 | 구현 |
| --- | --- | --- |
| `docs` | `docs.prj_id`가 속한 프로젝트의 `world_id`가 `docs.world_id`와 같다 | `prjs(id, world_id)`를 향한 복합 FK |
| `admin_prmsn_ruls` | 프로젝트 범위 허가의 `prj_id`가 지정한 `world_id`에 속한다 | `prj_id + world_id` 복합 FK, 프로젝트가 있으면 월드도 있어야 한다는 행 단위 검사 |

각 참조 컬럼에는 조회·삭제 검증에 필요한 인덱스를 별도로 둔다. 복합 FK의 대상은 PostgreSQL이 요구하는 비부분 고유 키여야 하므로, 소프트 삭제 조건을 붙이지 않는다.

### PostgreSQL 트리거로 표현하는 범위

아래 조건은 참조 행에 필요한 상위 범위 컬럼이 없거나, 시스템 공통 데이터와 프로젝트·월드 데이터를 함께 허용하므로 복합 FK만으로 표현할 수 없다. 생성·범위 변경 시 트리거가 검사하며, 과거 리비전이나 연결은 참조 대상이 나중에 삭제·비활성화되어도 보존한다.

| 영역 | DB가 유지할 범위 불변식 |
| --- | --- |
| 카테고리 | 사용자 정의 카테고리는 자기 프로젝트에만 속한다. 부모는 같은 프로젝트의 사용자 정의 카테고리 또는 시스템 기본 카테고리여야 한다. 시스템 기본 카테고리는 시스템 기본 카테고리 아래에만 둔다. |
| 프로젝트별 카테고리·템플릿 | `prj_ctgrys`의 사용자 정의 카테고리와 `prj_tmplts`의 사용자 정의 템플릿은 같은 프로젝트에만 연결한다. 대분류의 `prj_tmplt_id`는 같은 프로젝트의 프로젝트 템플릿만 가리키며 하위 카테고리에는 비운다. |
| 템플릿·리비전 | 이전 템플릿 리비전과 리비전 섹션·영속 섹션은 같은 템플릿 계보에 속한다. `tmplts.now_tmplt_rvs_id`는 자기 템플릿의 리비전만 가리킨다. |
| 문서·리비전 | 문서 리비전의 카테고리는 문서 프로젝트에 연결되어야 하고, 템플릿 리비전은 그 카테고리 대분류에 연결된 템플릿 계보여야 한다. 현재·공개 리비전은 자기 문서의 리비전만 가리킨다. |
| 문서 태그·링크 | 태그와 위키링크 대상 문서는 원본 문서와 같은 월드에 속한다. |
| 관계 | 월드별 관계 유형, 관계 참여 문서, 관련 문서, 관계 링크 대상은 모두 같은 월드에 속한다. 관계 참여 역할은 해당 관계 유형의 역할이어야 한다. |
| 초대·탈퇴 | 초대 허가의 프로젝트는 초대 월드에 속한다. 탈퇴 승계 월드는 탈퇴 계정 소유이며, 승계 대상은 그 월드의 부관리자여야 한다. |

트리거는 범위 일치만 보장한다. 새 문서에 비활성 카테고리·태그를 선택할 수 있는지, 관계 참여자의 현재 카테고리가 역할 허용 범위에 드는지, 삭제·공개·점검 상태가 행동을 허용하는지는 상태에 따라 달라지는 서비스 검증으로 둔다.

### 관계 참여 카디널리티

`rels`와 `rel_prtpnts`의 다음 불변식은 PostgreSQL 지연 제약 트리거로 커밋 시 검사한다.

1. 관계 참여 문서는 2개 이상 4개 이하다.
2. 같은 관계 안에 같은 문서를 두 번 넣을 수 없다.
3. 반복 불가 역할은 같은 관계에서 한 번만 사용할 수 있다.
4. 관계의 참여 문서·역할을 모두 만든 뒤에만 커밋할 수 있다.

관계 생성·수정 서비스는 관계 본체, 참여자, 해시, 이력을 하나의 트랜잭션으로 처리한다. 이 방식은 참여자 행을 순차로 넣는 중간 상태를 허용하되, 저장된 최종 상태에는 불완전 관계가 남지 않게 한다.

## 카테고리 깊이와 이동

### DB 제약

1. `ctgrys.prj_id`는 시스템 기본 `NULL` 또는 생성 때 지정한 사용자 정의 프로젝트에서 다른 값으로 바꿀 수 없다.
2. 시스템 기본 카테고리는 생성 뒤 부모·코드·사용·삭제 상태를 바꿀 수 없다. 시스템 카탈로그 적재만 예외이며 M02 시드가 이를 한 번 생성한다.
3. 사용자 정의 카테고리의 부모는 같은 프로젝트 또는 시스템 기본 카테고리만 허용한다.
4. 부모 포인터를 따라간 재귀 경로에 자기 `id`가 다시 나타나면 순환으로 거부한다.
5. 자신을 포함한 경로의 깊이가 4가 되는 삽입·이동은 거부한다. 따라서 최상위 카테고리부터 최대 3단계만 저장된다.

트리거는 `INSERT`, `prnt_ctgry_id` 변경, 금지된 `prj_id` 변경을 검사 대상으로 한다. 재귀 검사는 변경 후의 부모 경로 전체를 읽으며, 단일 행 `CHECK`로 대체하지 않는다.

### 동시 이동

같은 프로젝트의 카테고리를 동시에 옮기면 각 요청이 상대 요청의 미확정 부모 변경을 보지 못해 순환을 만들 수 있다. 이를 막기 위해 카테고리 구조를 바꾸는 트리거는 해당 `prj_id`에서 파생한 64비트 키로 PostgreSQL 트랜잭션 수준 advisory lock을 얻은 뒤 재귀 검사를 한다. 잠금은 커밋·롤백 때 자동 해제된다.

서비스는 카테고리 이동, 순서 변경, 영향받은 프로젝트 카테고리·문서·관계의 점검 상태 갱신을 하나의 짧은 트랜잭션으로 처리한다. DB 잠금 대기·교착 또는 직렬화 실패가 나면 저장 결과를 만들지 않고 기존 상태를 유지하며, 클라이언트는 자동 재시도하지 않는다.

## 템플릿·문서 최초 리비전 순환 참조

다음 FK는 Prisma 관계로 선언하되, 최초 마이그레이션 SQL에서 PostgreSQL `DEFERRABLE INITIALLY DEFERRED`로 바꾼다.

| 본체 | 리비전 | 지연 참조 |
| --- | --- | --- |
| `tmplts` | `tmplt_rvss` | `tmplts.now_tmplt_rvs_id → tmplt_rvss.id`, `tmplt_rvss.tmplt_id → tmplts.id` |
| `docs` | `doc_rvss` | `docs.now_doc_rvs_id → doc_rvss.id`, `docs.rls_doc_rvs_id → doc_rvss.id`, `doc_rvss.doc_id → docs.id` |

서비스는 본체 ID와 최초 리비전 ID를 먼저 만들고, 두 행과 최초 섹션·스냅샷을 하나의 트랜잭션에서 쓴다. 지연 FK와 범위 트리거는 최종 커밋 시점에만 검사하므로, 중간 SQL 문은 순환 참조를 가질 수 있어도 커밋 뒤에는 본체가 다른 대상의 리비전을 가리키거나 최초 리비전 없는 본체가 남을 수 없다.

일반 FK의 삭제 동작은 소프트 삭제를 처리하지 않는다. 소프트 삭제는 서비스가 공통 감사 컬럼을 갱신하는 상태 전이이고, FK의 `ON DELETE`는 탈퇴에 따른 완전 삭제처럼 실제 행을 제거하는 예외 흐름에서만 적용한다. 이때 구성 요소인 하위 자격증명·리비전 스냅샷·연결 행은 명시한 종속 관계로 정리하고, 다른 월드에 남는 작성자·수정자·삭제자 참조는 `SET NULL`로 보존한다.

## 행 단위 PostgreSQL 검사

다음은 다른 행을 읽지 않는 값이므로 Prisma 선언과 별개로 PostgreSQL `CHECK` 또는 필수 제약으로 남긴다.

| 구분 | 검사 |
| --- | --- |
| 공통 상태 | 모든 `use_yn`, `del_yn`과 개별 `*_yn` 컬럼은 `Y` 또는 `N`만 허용 |
| 범위 조합 | 전역 허가는 `world_id`, `prj_id`를 모두 비우고, 프로젝트 허가는 `world_id`도 반드시 가진다. 운영자 역할만 `world_id`를 비울 수 있다. |
| 세션 | `expry_dt`는 `lgn_dt`보다 뒤여야 한다. |
| 공개 슬러그 | 한글·영문·숫자·하이픈만 허용하고, 빈값·슬래시·URL 예약 문자를 거부한다. |

문서 이름의 최대 3개 구간, 비밀번호 형식, 시간에 따라 달라지는 세션 유효성, 공개·삭제·점검 상태에 따른 행동 가능 여부는 서비스 검증으로 둔다. 이들은 입력의 맥락 또는 현재 상태를 함께 보아야 하며, DB의 단순 값 제약으로 바꾸지 않는다.

## M02 구현 순서와 검증

1. Prisma 모델에 기본 키, 공통 컬럼, 일반 FK·고유 키와 `partialIndexes`를 선언한다.
2. 최초 마이그레이션을 생성 전용으로 만든 뒤, 대소문자 비구분 부분 고유 인덱스, `CHECK`, 지연 FK, 범위·카테고리·관계 트리거를 같은 마이그레이션에 추가한다.
3. 마이그레이션을 빈 테스트 DB에 적용하고, Prisma 검증·마이그레이션 상태 검사를 실행한다.
4. 서비스 계층이 생성·삭제·복구·이동·최초 리비전·관계 종료를 트랜잭션으로 실행하도록 구현한다.
5. 통합 테스트에서 Prisma 서비스 경로뿐 아니라 직접 SQL 삽입·갱신으로도 다음 DB 거부를 확인한다.

| 검증 영역 | 통과 기준 |
| --- | --- |
| 소프트 삭제 고유성 | 삭제된 동명·동슬러그 행 뒤 새 행을 만들 수 있고, 새 행이 있는 동안 기존 행 복구는 실패한다. 대소문자만 다른 활성 슬러그도 실패한다. |
| 범위 참조 | 다른 월드 프로젝트, 다른 프로젝트 사용자 정의 카테고리·템플릿, 다른 월드 태그·문서·관계를 직접 연결하려 하면 실패한다. |
| 카테고리 구조 | 동일 프로젝트·시스템 부모만 허용하고, 4단계·자기 부모·간접 순환·동시 순환 이동은 모두 실패한다. |
| 순환 리비전 | 템플릿·문서와 최초 리비전은 하나의 트랜잭션에서 성공하고, 다른 본체의 현재·공개 리비전을 가리키는 커밋은 실패한다. |
| 관계 | 참여자 1명 또는 5명, 중복 문서, 반복 불가 역할 중복, 다른 월드 문서 참여는 커밋되지 않는다. |
| 서비스 상태 | 비활성·삭제·권한 부족·공개 점검 미완료 대상의 행동은 서비스에서 먼저 거부하고, DB 위반 때에도 상태 변경과 이력이 남지 않는다. |

테스트는 `TEST_DATABASE_URL`만 사용하고, 대상 DB 이름이 `_test`로 끝나는지 먼저 검사한다. 실제 운영 DB와 개발 DB에는 제약 우회용 SQL을 실행하지 않는다.

## 범위 밖 항목

- 실제 Prisma 모델, 제약·트리거의 물리 이름, SQL 함수 본문, 마이그레이션 파일, 서비스 코드와 테스트 코드는 M02 구현 계획 및 구현 승인 뒤에 작성한다. 물리 이름이 새 공통표준용어를 필요로 하면 그때 표준용어 확인을 먼저 한다.
- 사용자 역할·권한·상태·공개 정책 자체를 바꾸지 않는다. 이 문서는 이미 확정된 규칙의 기술적 강제 위치만 정한다.
- PostgreSQL 이외 DB 지원, 임의 DB 직접 수정 운영 절차, 인덱스 성능 튜닝은 현재 범위가 아니다.
