# 옴니노드 요구사항 확정 작업 설계

> 분류: 작업 설계
>
> 목적: 서비스 요구사항을 마스터와 한 항목씩 확인하고, 확정 즉시 프로젝트 설계 문서에 보존하는 작업의 진행 규칙을 기록한다.

## 질문 구분 규칙

모든 질문의 첫머리에 아래 성격 중 하나를 명시한다.

- **기능 정책**: 서비스가 무엇을 할 수 있는지, 데이터가 어떻게 동작·보존되는지, 권한과 예외를 어떻게 처리하는지를 정하는 질문
- **화면·상호작용 구조**: 화면의 구성, 목록·탭·필터, 버튼·드래그 같은 조작 방식을 정하는 질문

두 성격이 함께 필요한 경우에는 한 질문으로 섞지 않고, 먼저 기능 정책을 확정한 뒤 화면·상호작용 구조를 별도 질문으로 확인한다.

## 진행 우선순위

기능 정책 검토가 종료되기 전에는 화면·상호작용 구조 질문으로 넘어가지 않는다. 화면 구조는 기능 정책이 충분히 확정된 뒤 별도 단계에서 다룬다.

## 질문 필요성 점검

새 질문을 하기 전에 기존 확정 결정의 직접적인 결과인지 확인한다. 이미 정한 기준으로 결론을 낼 수 있는 사항은 마스터에게 다시 선택을 요구하지 않고, 파생 규칙으로 정리해 기록한다. 서로 다른 정책이 실제로 가능한 경우에만 선택지를 제시한다.

## 보류한 화면 설계

- 관리자 운영 화면에서 월드·프로젝트 목록을 어떤 계층으로 탐색할지는 현 단계에서 결정하지 않는다. 기능 정책과 화면 구조 설계를 분리해, 화면 설계 단계에서 다룬다.

## 기록 절차

1. 마스터의 선택 또는 직접 지시를 받은 즉시 `docs/project-design/2026-08-29-omninode-requirements-decisions.md`에 기록한다.
2. 기록 뒤 `git diff --check`로 문서 형식 오류를 확인한다.
3. 다음 질문에서는 질문 성격을 먼저 밝히고, 선택지를 제공한다.
4. 미결로 남긴 항목은 확정 결정과 섞지 않고 같은 프로젝트 설계 문서의 `미결 결정`에 유지한다.
