# 옴니노드 데이터 스키마 간 점검

> 분류: 작업 설계
>
> 점검 대상: `2026-08-29-omninode-data-schema.md`와 1차 기획·사용자 스토리·유스케이스·데이터 플로우의 확정 정책
>
> 범위: 테이블 간 참조, 범위 제약, 리비전 계보, 삭제·복구, 공개 상태, 권한, 탈퇴 흐름의 정합성을 점검한다. ORM, DDL, 마이그레이션, 구현은 포함하지 않는다.

## 점검 결과

| 점검 영역 | 결과 | 반영 내용 |
| --- | --- | --- |
| 공통 식별자·공통 컬럼 | 통과 | UUID v7, 복수형 `snake_case`, 공통 8개 컬럼과 `Y`·`N` 규칙이 모든 설계 대상에 일관되게 적용되어 있다. |
| 월드·프로젝트 범위 | 보완 완료 | 월드 이름 중복 기준을 현재 소유자가 아닌 생성자로 명확히 하고 데이터 플로우 표현도 같은 기준으로 맞췄다. |
| 관리자 역할·24개 허가 | 보완 완료 | 한 계정의 전역 운영자 역할과 월드별 역할의 중복을 막고, 전역·월드·프로젝트 허가의 적용 우선순위를 명시했다. 관계 관리는 관계 유형과 실제 관계 인스턴스를 함께 다루는 8번째 관리 대상이다. |
| 기본·사용자 정의 데이터 | 통과 | 기본 카테고리·템플릿·관계 유형은 복제하지 않고 참조하며, 사용자 정의 항목은 각 프로젝트 또는 월드 범위를 가진다. |
| 템플릿 섹션 코드·리비전 | 보완 완료 | 변경 불가 섹션 코드를 영속적으로 관리하는 `tmplt_sects`를 추가하고, 리비전별 섹션이 이를 참조하도록 했다. 새 템플릿 리비전에는 기존 섹션을 빠뜨릴 수 없게 했다. |
| 문서·템플릿 리비전의 순환 참조 | 보완 완료 | 템플릿·문서와 최초 리비전은 한 트랜잭션으로 만들고, 생성 중에만 현재 리비전 참조를 비워 둘 수 있게 명시했다. 완료 시에는 최초 리비전을 반드시 가리킨다. |
| 문서 세계관 시점·공개 주소 | 보완 완료 | 문서 리비전에 세계관 안의 시작·종료 시점을 각각 선택 문자열로 보존하고, 생성자가 직접 입력하는 공개 주소용 월드·프로젝트 변경 불가 슬러그를 UUID와 별도로 추가했다. 월드 슬러그는 전역, 프로젝트 슬러그는 월드 범위에서 유일하다. |
| 카테고리 이동 점검·공개 중단 | 보완 완료 | 문서·프로젝트 카테고리 연결·관계에 `ctgry_mvmn_chck_yn`을 두어 점검 필요 상태와 완료 상태를 저장한다. 점검 필요 문서는 즉시 비공개가 되며, 수동 완료 전 공개할 수 없다. |
| 위키링크·태그·관계 | 통과 | 문서 리비전별 링크와 태그, 관계의 현재 상태와 이력이 분리되어 있으며 삭제·비공개 표기 정책과 충돌하지 않는다. |
| 초대·비밀번호 재설정 | 통과 | 초대 재발송은 기존 링크·만료·권한을 보존하고, 비밀번호 재설정 재요청은 기존 대기 링크를 무효화하는 서로 다른 흐름으로 분리되어 있다. |
| 계정 탈퇴·데이터 내려받기 | 보완 완료 | 내려받기 결과가 탈퇴 확정 뒤 다른 관리자의 변경에 영향받지 않도록 탈퇴 확정 시점 스냅샷을 `admin_whdwl_reqs.dwnld_data_json`에 보존하도록 했다. |

## 표준용어 확인

카테고리 이동 점검 상태의 새 물리 식별자는 공통표준단어 시트에서 확인한 카테고리 `CTGRY`, 이동 `MVMN`, 점검 `CHCK`을 조합해 `ctgry_mvmn_chck_yn`으로 기록했다.

## 점검 종료 기준

- 테이블·참조·범위·리비전·삭제·공개·탈퇴 흐름의 기술적 정합성 보완을 완료했다.
- 관계 관리는 기존 24개 허가 체계의 여덟 번째 관리 대상이며, 관계 유형과 실제 관계 인스턴스를 함께 관리한다. 별도 미결 기획 항목은 없다.
